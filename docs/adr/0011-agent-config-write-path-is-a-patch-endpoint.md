# Agent 配置的写路径是一个 PATCH 端点，「暂停」复用它、不改唤醒面

Agent 配置（`agent_config` 表：`role` / `model_id` / `system_prompt` / `enabled`）今天只有读路径（`GET /api/agents`、`GET /api/agents/{id}`），没有任何写路径，因此「编辑配置」与「暂停」两条动作在人类面都无法完成。我们决定新增一个 `PATCH /api/agents/{id}`，在同一写路径上承载显示名与全部配置字段，并把它**定义为配置变更而不是对话动作**：它不落任何消息、不唤醒任何人、不消耗回应预算、也不开人类世代。ADR-0005 的动作词汇表只覆盖任务（改指派 / 改状态 / 改标题），Agent 配置不在这张表里，因此不构成例外——它压根不是一次「发言」。

`display_name` 也允许改：`CONTEXT.md` **提及** 已写明解析结果（含位置）随消息落库，成员改名不让历史提及漂移，所以改名在本仓是安全动作。`model_id` 沿用与创建同一套校验（`provider:model`、缺凭证时的可读原因、远端 provider 的**远端数据流告知**）；改到远端 provider 时状态点由既有 `availability` 推导为**未启用**并给出可读原因，不需要新机制。

**「暂停」= 写 `enabled = 0`**，即复用既有可用性判定，而不是发明一个新状态。它的已知代价必须写清楚：暂停**不把该 Agent 排除出唤醒面**——它仍会被唤醒、仍会跑一轮、仍会落下一条 `failed` 轮次结果（原因「该 Agent 的模型配置已停用」），只是不产出回复、状态点为**未启用**。这与今天任何不可用原因（未配置模型 / 缺凭证 / 未确认远端告知）的行为完全一致，不存在第二套规则。把「暂停」实现成「从唤醒面排除」（真正零轮次、零记录）是唤醒面的另一个决策，本轮不做，已登记在规格的 Out of Scope。

该写路径由用户于 2026-10-16 点名的「Agent 详情并且可以编辑」授权；写路径的具体字段集与校验口径属于实现细节，记录在 `app/specs/issue-60-spec.md` 的决策账。
