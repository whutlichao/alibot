# 派任务与有界响应同构：唤醒的载体是「指派」这个动作

任务需要"把活派给某个 Agent"，而被派的人得**知道**自己被派了。这里有一个容易混淆的接缝：任务是**可变**的
（要能改状态、改指派），但如果每次改都唤醒一次，看板上"活干到哪了"的每一次点击都会变成一次 agent 往返，
噪声和 token 都会失控。

我们决定把**动作**和**字段**分开：**唤醒的载体是「指派」这个动作，而不是「状态从 todo 到 in_progress」
这个动作**。于是三条路径各有明确后果——

- **改指派人**：owner 派给某 Agent = 一次**人类发言**（开启新**人类世代**、该 target 的**回应预算**重置为 3、
  唤醒被指派者）；Agent 转派给别人 = **一次 agent→agent 跳**（消耗 1/3）。
- **改状态**：**永远不唤醒**，因此不消耗预算、`target_budget.used` 不动。它在任务 target 的消息流里留一条
  `system` 消息，仅此而已。
- **改标题**：同"改状态"，不唤醒。

我们选它，而不是"任何任务变更都唤醒"或"任何任务变更都不唤醒"：前者把**看板操作**变成**发言**，会让预算被
UI 点击烧掉；后者让"我被派了活"变成一件需要自己去翻看板才知道的事，与 #1 的"唤醒是注意力信号"背道而驰。
这条决策是 ADR-0002 的直接应用而非例外——**跳**的定义没变（一条 Agent 消息投递了至少一个唤醒给其它 Agent），
只是明确了"哪种任务动作构成一次投递"。

代价是任务的**动作词汇表**比字段表小：实现时必须区分"改指派人"与"改状态"两条写路径，不能合并成一个
`update_task(fields)` 了事。这个代价是值得付的——它把"什么会惊动别人"变成一条读代码就能看出的规则。

一处必须写准的落地细节：`epoch_seq` 记的是**开世代动作所在那条消息的 seq**，而不是"最近一条 `human` 消息的
seq"。因为 owner 改指派落的是 `system` 消息（见上面那张动作表），若把世代标识绑死在 `human` 上，这次重置就
没有 seq 可指。被否的替代方案（owner 改指派额外再落一条 `human` 消息）会让一条动作产生两条消息，
与"一次变更一条记录"相冲，也不采纳。
