# 消息 append-only，不可编辑、不可删除

人与其 Agent 在同一个频道里协作，消息是双方共同的事实的载体。我们决定**消息是 append-only 的永久记录**：
不存在更新或删除消息的代码路径（`db.py` 的库级触发器 `message_no_update` / `message_no_delete` 兜底，
任何未来代码路径与人工 SQL 都被拒绝），HTTP 面也没有编辑或删除端点；人类与 Agent 的消息一视同仁。

考虑过的另一条路是"成员或作者可撤回自己的消息"。我们否掉它，因为撤回会让"我们当时达成的共识"变成
不可依赖的东西：任何一方都能在事后改写记录，追溯与验收就失去了共同基准。**成员删除**因此也做成
soft-delete（行保留以承载作者渲染，只移出频道），这一点由同一条理由决定：历史消息的作者不能被抹掉。

代价是明确的：写错的内容只能用新消息纠正，库会一直长。这是为"可依赖的审计面"付的代价。
