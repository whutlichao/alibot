# 回应预算 ≤ 3 是有界响应的手段

Agent 之间可以互相被消息唤醒（一条 Agent 消息唤醒另一个 Agent = 一次 **agent→agent 跳**）。若不设上界，
两个 Agent 会互相唤醒到把 token 烧光。我们决定：**每个频道的每个人类世代（最近一条人类消息的 seq）内，
agent→agent 跳数硬上界为 3**；人类消息落库即开启新世代并把预算重置为 3。

关键取舍在于**上界怎么实现**。我们选了"耗尽的世代里一个唤醒都不投递"，而不是"投递后发现超限再刹住"或
"事后统计告警"：只有"零投递"能让上界成为**构造性**保证（可被断言，而不是被观察）。Agent 消息在预算耗尽时
**照常落库**——不可撤回是 ADR-0001 定的，预算约束的是**唤醒**而不是记录。轮次结果里那次 `budget-exhausted`
是"它没说话"的可解释来源，且**不是出错**，成员状态点仍是空闲。

预算状态落库（`channel_budget`）而不是放进程内存，因此"已用 / 剩余"在后端重启后仍是同一条事实。
一次跳即使唤醒多个成员也只消耗 1 次，所以**跳数的正本是 `channel_budget.used`，不是轮次结果的行数**。
