# 认领是编排发起的指派动作：它不是跳，但开一次世代，且每张任务至多一次

用户于 2026-10-16 人定「新建任务后 Agent 主动认领」要**真做行为**（Agent 配置开关 + 编排认领），并就它的预算语义给出裁定。本 ADR 记录那次裁定与它的边界。

**背景与代码现状。** `docs/adr/0005-dispatching-a-task-is-a-human-utterance.md` 把「改指派人」分成两格：owner 改派 = 一次**人类发言**（开启新**人类世代**、重置预算、唤醒受派者）；Agent 转派**给别人** = 一次 **agent→agent 跳**（消耗 1）。**认领两者都不是**：它把**未指派**的任务指派给**自己**——没有"别人"被投递。代码现状更直接：`app/alibot/db.py` 的 `update_task_assignee` 要求 `previous_id == actor_member_id`，于是 Agent 认领未指派任务**直接被拒绝**；也就是说认领今天不存在，它必须是一条新增的写路径，而不是既有端点的另一种用法。

**一、认领由编排发起，不扩大成员面接缝的形状。** 任务创建后由后端按该频道的 Agent 配置裁决谁认领，**不让模型自己改数据库**：**成员面适配接缝**的输出仍然是「零或多条待落库回复 + 一个轮次结果」，不新增第三种输出。

**二、认领不是一次跳。** `CONTEXT.md` **跳** 的定义是「一条 **Agent 消息**投递了至少一个唤醒给其它 Agent」；认领的载体是任务型 target 上的一条 `system` 记录，而 `system` 记录不是对话回合、不触发通用唤醒——这与 ADR-0005 里「改状态 / 改标题不唤醒」同族。认领**唤醒认领者本人**这一下是**指派动作**的载体效应（与 owner 指派走同一条既有唤醒路径），不是一条 Agent 消息的投递，因此不计入跳数。

**三、认领开一次世代。** 首次认领把该 task target 的**人类世代**推进到这条 `system` 记录的 seq，并按**当世代生效的回应预算上界**把 `used` 重置为满额。于是开世代动作从两种变**三种**，第三种由**编排**发起（前两种见 `CONTEXT.md` **人类世代**）。

**四、每张任务至多一次。** 认领只对「从未被认领过」的任务成立。这条限制不是礼节，它是 **ADR-0002** 的三跳上界**仍然可执行**的前提：若每次认领都能重置预算，Agent 就能靠「认领 → 用满 → 再认领」把「一次人类发言能引发多少 Agent 往返」这道闸门拆掉。因此「每任务一次」是**构造性保证**，必须由后端裁决，不能靠界面不给按钮。

**五、与 ADR-0005 的关系：扩展，不是推翻；原文不改。** ADR-0005 的动作表从此多一格——指派人变更（owner）/ 指派人变更（Agent 转派）/ 改状态 / 改标题 / **认领**；「唤醒的载体是**指派**这个动作」这条判断不变，认领正是它的又一次应用。**不改 ADR-0005 原文**，理由与 ADR-0007 处置 ADR-0002 同构：那份 ADR 记录的是当时那次决策与**被否的替代方案**，就地改写会让「当时为什么这么定」消失。

**代价（明确登记）。**
- **「人类世代」这个名字不再字面准确**：它现在覆盖三种开世代动作，其中一种由编排发起。我们**不改名**——改名会同时扯断代码注释、文档与取证面里的全部存量引用，收益只是名称直观；代价由本 ADR 与 `CONTEXT.md` 词条里的 inline 说明承担。
- **认领是一次真实的注意力投递**（它唤醒认领者），只是不计入跳数；这条边界靠本 ADR 与「每任务一次」两条一起守。
- **认领是配置层的确定性规则，不是模型的判断**：Agent 不会"申请"认领，`auto_claim` 开关决定编排要不要替它接手。
