# Agent 只有结构身份，不经 HTTP

Agent 需要在频道里以"某个成员的名义"说话。有两条路：给每个 Agent 一份**凭证**（令牌），让它经 HTTP
调用后端；或者让身份**由调用点决定**。我们选后者，并把这条边界定死：**Agent 的任何动作都由后端进程内
直接执行，不经 HTTP**——HTTP 面自始至终属于人类面（浏览器与人自己的脚本），协作面整体只经进程内接缝
服务成员面。

理由是可伪造面的大小。自述凭证有三个属性我们都不想要：**可伪造**（拿到就能冒充）、**可转发**（不落痕迹
地换人用）、**必然可被持有它的调用者读出**（agent 能读到自己的令牌）。结构身份一个都没有——"驱动某一轮时
它代表哪个成员"本来就是唤醒编排手里的已知事实，写进代码即可，不需要一条声明。首版因此不引入 agent 令牌，
也不做"以某成员名义调 HTTP"的路径。

代价是 Agent 的每一次动作都要由编排在进程内发起，无法把 Agent 拆成独立进程或远端服务。对本机单用户的
首版形态，这不是限制。
