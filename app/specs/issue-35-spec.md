## 规格票：Agent 的括注 / 旁白 —— 把「说了等于没说」收敛到可实施的沉默规格

**票型**：规格票 ｜ **门禁**：G-spec ｜ **本票不跑**：源码测试、双轴 code-review、实施门禁 G-impl

Part of #1（首版规格锚点）。**本票是「沉默」这件事的规格正本**，与 #22 / #23（第二版能力扩展规格）平级、互不修改：
#22 把 `target` 升为一等对象并开出三块能力；本票**只收敛一件事**——Agent 用括注 / 旁白交代「我为什么没说话」
时，那串文字到底算不算一次发言。本票**不产出实施票**、不改任何 `app/` 下的代码。

## Problem Statement

我在频道里让 Agent 旁听，或者 @ 了它但这一轮其实没什么可说的。它回了我一条消息，正文是：

> （本轮消息与我无关，无需回应）

这条消息在界面上**和一次真实回复长得一模一样**：同样的头像、同样的 `Agent` 标签、同样占一行、同样推进未读徽标。
但它什么都没说——它只是把「我不需要说话」这个结论**当成一句话说了出来**。于是我从消息流里读不出「它克制地没说话」，
只读出一句客套话；而真正克制没说话的那些轮次，在前端只是 #18 那行默认折叠的摘要（`它没有回应 · 展开看原因`）。

代价不只是观感。这类旁白消息走的是**普通发言路径**，所以它：

- **占 `seq`、计入未读徽标**——我因为一句「无需回应」多了一个未读；
- **照常唤醒别的 Agent 并消耗预算**——它触发一次 agent→agent 跳，把人类世代里的 3 次上界烧掉一格；
- **不可撤回**——ADR-0001 定死 append-only，我事后既不能删也不能编辑这条等于没说的话。

我想要的区分很简单：**「它没有说话」和「它说了一句等于没说的话」必须在界面上与账本上都是两件事。**

### 代码事实（coordinator 只读核实，本轮不重查）

1. **现象消息是真实的 `kind="agent"` 消息，走普通回复路径。**
   `app/alibot/agent_seam.py:255` 的判定是「正文 `strip()` 非空 ⇒ `status="replied"`」
   （`RoundOutcome(status="replied", …, messages=[RoundMessage(body=text)])`，`app/alibot/agent_seam.py:256-258`）；
   随后经 `app/alibot/orchestration.py` 的 `_commit_reply`（`app/alibot/orchestration.py:472`，本仓**唯一**的
   Agent 消息落库路径）→ `app/alibot/db.py` 的 `append_message`，后者只校验正文非空
   （`clean_body = (body or "").strip()` / `if not clean_body: raise …`，`app/alibot/db.py:692-694`）。
2. **没有任何标识区分它与真实回复。** `MESSAGE_KINDS = ("human", "agent", "system")`（`app/alibot/db.py:42`）里
   没有第五种值可用，前端 `msg-tag` 对它只会渲染成 `'Agent'`（`app/alibot/studio/app.js:1203`）；
   未读口径也算它——未读计数只按 `kind IN ('human', 'agent')` 且非作者自身（`app/alibot/db.py:199-203`）。
3. **这类消息照常触发后续唤醒并消耗预算。** `notify` 只对 `kind == "system"` 早退
   （`if message["kind"] == "system": return 0`，`app/alibot/orchestration.py:173-174`），而 agent 作者 + 目标非空
   就走一次 agent→agent 跳（`jump_delivered = author_kind == "agent"` + `_spend_jump`，
   `app/alibot/orchestration.py:184-188`）。
4. **真正被模型判为沉默的那条路径是 `RoundOutcome(status="ignored")`：不落消息、只在 `round_outcome` 留一条记录。**
   它由「模型没有产出可落库的正文」触发（`app/alibot/agent_seam.py:254-255`），在库里表现为一条 `round_outcome` 行
   （status 词表见 `app/alibot/db.py:45`），在前端表现为 #18 那行折叠摘要
   （`app/alibot/studio/app.js:997` 的 `roundOutcomeSummaryNode`，折叠态文案见 `app/alibot/studio/app.js:1021`）。

**这四条的合起来的意思**：今天「沉默」与「旁白」在数据面上**不是同一种东西**——沉默有账（`round_outcome`）、
旁白有消息（`message`）；但只有消息在消息流里长得像发言，而它恰恰什么都没说。本票要定的是把它们收敛到同一侧的判据与路径。

## Solution

把「Agent 没有实质内容要说」这件事从**发言**这一侧搬到**沉默**这一侧，并让它在每一层都可解释：

```text
今天（旁白即发言）
  模型输出 "（本轮无需回应）"
    → agent_seam：正文非空 ⇒ status="replied"
    → orchestration._commit_reply → db.append_message(kind="agent")   # 占 seq / 计未读 / 触发一次跳
    → 前端：一条普通 Agent 消息（msg-tag "Agent"）

目标（沉默有账、旁白不成消息）
  模型声明「本轮沉默」（阶段 3 的结构化信号；阶段 1/2 靠 prompt 纪律 + 最小判据）
    → agent_seam：判为沉默 ⇒ status="ignored"，零待落库回复
    → orchestration：不落消息、只落一条 round_outcome（不占 seq / 不计未读 / 不构成一次跳）
    → 前端：#18 既有的一行折叠摘要「它没有回应 · 展开看原因」
```

### 交付是**三个阶段**，每一步各自能单独交付（coordinator 已裁定：两阶段路线）

四条诉求不是四个并列方案，而是**一条演进路线上的三步**——每一步都有自己独立的价值，
每一步都要单独回答两个问题：**它能单独交付什么**、**什么条件下才值得进下一步**。

| 阶段 | 内容 | 单独能交付什么 | 进下一阶段的条件 |
| --- | --- | --- | --- |
| **阶段 1：先修 prompt 纪律**（第 4 条） | 修掉系统提示里那句自相矛盾的括注，把「沉默」从**输出格式要求**改成**结论要求** | 零代码改动、成本为零；直接降低旁白发生率；给出可复现的归因（提示本身在示范「简短说明」这种输出形态） | 触发条件：**旁白仍在发生**（提示是概率性的，给不出正确性保证）。若修完提示后旁白不再出现，阶段 2 / 3 可暂缓——但**不能**因此认为问题已解决（模型 / 措辞换一次就可能复发） |
| **阶段 2：seam 层最小可判据**（第 2 条） | 在适配层把「无实质内容的输出」归为 `ignored` 一侧 | **正确性落在后端**，不再依赖模型守规矩：兼容既有数据与不听 prompt 的模型；未读 / 预算 / 唤醒污染三处同时解决 | 触发条件：**判据开始说谎**（换模型 / 换语言 / 换措辞使判据失效，或误伤了真实短回复）。判据本身就是「措辞表」这个结构性弱点，只有阶段 3 能消掉 |
| **阶段 3：结构化沉默信号**（第 3 条，目标态） | 让模型**显式声明**沉默，后端读字段而不读文本 | 判据问题被**消掉**而不是被回答：不再有「什么算无实质内容」的猜测；每个 provider 的结构化输出能力差异成为唯一的落地成本 | —（目标态） |

三个阶段的边界必须写清，避免被读成「阶段 1 就够了」或「直接跳到阶段 3」：

- **阶段 1 不替代阶段 2**：提示是**概率性**的，判据是**确定性**的。前者降低发生率，后者给出保证。阶段 1 单独交付时，
  「旁白仍是消息」这件事在数据面上没有任何变化。
- **阶段 2 不替代阶段 3**：阶段 2 的判据必然是一张措辞表（或一组启发式），它的可靠性上限就是「我猜得准」。
  阶段 3 把猜测换成声明，是**判据来源**的改变，不是判据的调优。
- **阶段 3 需要先修 prompt**：结构化声明要让模型知道「有一条表达沉默的通道」，而现行提示恰恰在教它用括注
  （`app/alibot/agent_seam.py:273`）。跳过阶段 1 直接做阶段 3，模型仍会在「必须回应」与「声明沉默」之间找中间态。
- **呈现层（第 1 条）横跨三阶段**：历史旁白已经落库、不可撤回（ADR-0001），所以无论走到哪一阶段，
  呈现层都必须能对**已经存在**的旁白降档；它是唯一一条不依赖判据正确性的路径。

### 阶段 1 的评估结论（第 4 条诉求）

先行确认现行系统提示是不是在**诱导**括注。现行原文是
「回应纪律：被个人提及（@你的名字）时必须回应；话题明确与你无关、或你没有被点名时，**应当保持沉默
（只回一个空字符串之外的简短说明不算回应）**。」（`app/alibot/agent_seam.py:270-274`，其中第 273 行）。
这句话的问题在于**语义自相矛盾**：前半句要它沉默，后半句的括注却把「简短说明」明确排除在沉默之外——
模型最省力的合规解就是回一句简短说明。
**结论：这句话确实在诱导括注**，完整归因与改写方向见 Implementation Decisions §D5。

## User Stories

### A. 消息流读起来像对话

1. 作为本机用户，我想在消息流里一眼看出某个 Agent 这一轮「没有说话」，而不是读到一句「我无需回应」，这样我不会把客套话当成一次发言。
2. 作为本机用户，我想这类「无实质内容」的消息不再和真实回复抢同样多的注意力（更轻的视觉权重、或收进一行摘要），这样长对话不会被旁白撑散。
3. 作为本机用户，我想点开那行摘要时能读到**为什么**（后端 `reason` 原文），这样「它沉默」是可解释的而不是没反应。
4. 作为本机用户，我想在同一个 Agent 连续多轮沉默时，消息流不会因此多出多行噪声。
5. 作为本机用户，我想「它没有说话」的呈现**沿用 #18 已经确立的形态**（一行、默认折叠、可展开、键盘可操作），这样我不需要学第二套视觉语言。

### B. 未读与预算不再被旁白污染

6. 作为本机用户，我想旁白式交代不再推进未读徽标，这样徽标只代表「有人真的对我说了话」。
7. 作为本机用户，我想旁白式交代不再消耗人类世代的 3 次 agent→agent 跳预算，这样预算留给真实的接力。
8. 作为本机用户，我想预算条 / `target_budget.used` 的读数不因旁白而虚增，这样「还剩几次」是可依赖的。
9. 作为本机用户，我想旁白不再唤醒其它 Agent，这样一句「无需回应」不会引出一串没必要的往返。

### C. 账本可解释、可取证

10. 作为本机用户，我想每一轮**恰好**落一条轮次结果（`round_outcome`），无论它是发言还是沉默，这样「这一轮它做了什么」只有一个查询入口。
11. 作为本机用户，我想从一条轮次结果能判断这一轮是「自判沉默」还是「处理失败」，这样我不会把克制的沉默当成故障。
12. 作为本机用户，我想「这一轮模型声明了沉默」这个事实在 `reason` 里可读，这样我能分清「模型自己说要沉默」与「后端替它判的」。
13. 作为本机用户，我想验收时能断言「这次唤醒没有产生任何 message 行」，这样这条规格是可被机器判定的而不是靠肉眼。
14. 作为本机用户，我想历史里已经落库的旁白消息保持原样（不可编辑、不可删除），这样我对「当时说过什么」仍有可依赖的审计面。

### D. 模型侧的纪律与信号

15. 作为 Agent 配置的维护者，我想系统提示明确区分「沉默」与「用一句话交代沉默」，这样模型不会把交代当成沉默的合规解。
16. 作为 Agent 配置的维护者，我想系统提示不再写出「只回一个空字符串之外的简短说明不算回应」这类自相矛盾的括注，这样指令人可读、模型可执行。
17. 作为 Agent 配置的维护者，我想模型**显式声明**「本轮沉默」而不是让我事后猜，这样判据不依赖措辞。
18. 作为 Agent 配置的维护者，我想沉默声明在**不改变 `MESSAGE_KINDS`** 的前提下表达（消息仍只有 human / agent / system 三种），这样这条规格不动消息域的既有形状。
19. 作为 Agent 配置的维护者，我想「一轮 ↔ 至多一条消息」的契约在引入沉默声明后仍然成立且被强校验，这样并发与预算的既有推理不受影响。

### E. 面向实现与测试

20. 作为实现者，我想「什么算无实质内容」有一个**被显式裁定的**判据（而不是散落在代码里的一句正则），这样我改措辞不会悄悄改行为。
21. 作为实现者，我想判据的失败模式是**显式**的（宁可判成发言、也不吞掉真实回复），这样误判的方向是安全的。
22. 作为实现者，我想这条规格的可观察验收落在**既有的高层接缝**上（发消息 → 落库 → 唤醒 → 追加回复 → 前端实时呈现），这样我不需要新开一条 seam。
23. 作为实现者，我想测试能用既有的脚本化替身把「回应 / 忽略 / 失败 / 延迟」四种行为固定下来，这样验收不联网、零成本。
24. 作为实现者，我想前端呈现的验收沿用 #18 已有的用例族，这样摘要行不是第二套实现。
25. 作为实现者，我想这条规格不授权我顺手改其它呈现代码（预算可视化、轮次全览页），这样范围不扩散。

### F. 边界

26. 作为本机用户，我想「沉默」这个词在本仓有一个明确定义、且与它的反面词（把沉默说出来）在词汇表里分开，这样票面、代码注释与界面文案说的是同一件事。
27. 作为本机用户，我想这条规格明确说出它**不**做什么（不产实施票、不改代码、不做内容质量评分），这样下游不会把它当成一张实施授权。
28. 作为本机用户，我想如果某条诉求会推翻既有 ADR 或契约，规格里显式指出来并说明需要新 ADR，这样决策不会被静默绕过。

### G. 分阶段交付

29. 作为本机用户，我想先拿到「修 prompt 纪律」这一步的单独交付（零成本、先降低旁白发生率），这样我不必等后端判据就得到改善。
30. 作为本机用户，我想知道阶段 1 交付后**问题并未解决**（提示是概率性的），这样我不会把发生率下降误当成正确性保证。
31. 作为本机用户，我想在阶段 1 之后能判断「该不该进阶段 2」（看旁白是否仍在发生），这样路线推进不靠感觉。
32. 作为本机用户，我想在阶段 2 之后能判断「该不该进阶段 3」（看判据是否开始说谎 / 误伤真实短回复），这样阶段 3 是一个有条件的接续而不是默认必做项。
33. 作为本机用户，我想阶段 2 的判据被允许是**临时的**（只要失效方向安全、并写明将被阶段 3 取代），这样我不会因为要求判据一次到位而无法先落地。
34. 作为本机用户，我想阶段 3 落地前先确认模型侧的结构化输出能力（不同 provider 支持度不一），这样目标态不会被当成不花钱的事。
35. 作为本机用户，我想呈现层降档不被任何阶段卡住（它不依赖判据裁定），这样历史旁白能被最早处理。

## Implementation Decisions

### 术语（本票裁定，写进 `CONTEXT.md` 的依据）

- **沉默 (Silence)**：一轮的结论是「我不需要说话」——对应已落库的 status 词 `ignored`（「自判忽略」）。
  它是**正常协议选择，不是失败**（沿用 #1「回应判断」词条）。规格里说「用户可见语义」时用「沉默」，
  指**落库字段值**时用 `ignored`，两者不混用。
- **旁白式交代 (Silent Narration)**：**反面词，进 `_Avoid_`**。定义：Agent 把「我不需要说话」这个结论
  **当作正文说出来**，于是它成为一条真实的 `kind="agent"` 消息。它**不是**沉默——它走发言路径
  （占 `seq`、计未读、构成一次跳）。
  _Avoid_：沉默说明、空回应、括注消息（这三个词都把「说了等于没说」读成一种低配版回应，正是本票要消掉的读法）。
- 术语理由：本仓既有词条都是「中文词 (English Term)」，且对易混词用 `_Avoid_` 划界；
  「旁白式交代」被显式否掉、不作为正式术语，是为了让**其它票面不得再把它当成一种回应类型**来引用。

### 已定（规格层面拍板，实施必须遵守）

- **D0-a｜收敛方向已定**：这类输出最终必须落到**沉默**一侧（不落消息、只落轮次结果），而不是继续当发言。
- **D0-b｜不动消息域形状**：不新增 `MESSAGE_KINDS` 值（仍是 `human` / `agent` / `system`，`app/alibot/db.py:42`）。
  旁白不是「第四种消息」，它是一个**不该成为消息的输出**。
- **D0-c｜历史不可改**：已落库的旁白消息**不得**回填、编辑或删除（ADR-0001 硬约束）。因此任何「把历史旁白洗干净」的
  方案都不成立；能做的只有**呈现层对既有消息降档** + **新消息不再这样落库**。
- **D0-d｜「一轮 ↔ 至多一条消息」契约不放松**：`RoundOutcome.__post_init__` 的强校验
  （`len(self.messages) > 1 → ValueError`，`app/alibot/agent_seam.py:118-121`）继续作为不变量；
  任何结构化沉默信号的引入都要与它**互斥校验**（声明沉默 ⇒ 零条待落库回复），而不是绕开它。
- **D0-e｜呈现层沿用 #18 的手法**：一行、默认折叠、展开后给后端 `reason` 原文、原生 `<button>` +
  `aria-expanded` / `aria-controls`（`app/alibot/studio/app.js:997` 及其折叠控件实现）。
  **不新造第二套视觉语言**，也不新造色位（按名字消费设计系统 token）。

### D1｜阶段 2 的 ⏳ 待定决策点（本票最大未决项）：什么算「无实质内容」的可靠判据

**判据来源的路线已定（阶段 2 → 阶段 3，见 Solution），但「阶段 2 用哪个最小判据」本票不裁定，只列候选与代价。**
四个候选，均未拍板（候选-2 属于阶段 3，列在这里是为了让「阶段 2 的判据 vs 阶段 3 的目标态」能对照着看）：

| 候选 | 做法 | 代价 / 风险 |
| --- | --- | --- |
| **判据-1：seam 层文本启发式** | 在适配层用正则 / 白名单识别「整条正文被括注包裹」或「命中一组固定说法」，命中即判沉默 | 判据是一张**措辞表**，模型换一个说法就失效；误伤真实短回复（「好。」「收到」）方向不安全；每换模型 / 换语言都要重维护；**把不可靠的猜测固化成正确性判据** |
| **判据-2：模型结构化声明**（= 第 3 条诉求） | 让模型输出里带一个显式的「本轮沉默」字段（structured output / 工具调用），后端读字段而不读文本 | 需要模型侧具备结构化输出能力（不同 provider 支持度不一）；`RoundOutcome` / 替身 / 测试都要跟着扩；收益是**判据不再是文本启发式** |
| **判据-3：空正文 + 约定的哨兵值** | 约定一个无自然语言歧义的哨兵串（如 `NO_REPLY`），模型只回哨兵即判沉默 | 仍靠模型遵守格式；哨兵有被写进正文并**泄漏给用户**的风险；比正则稳、比结构化弱，中间态 |
| **判据-4：只做呈现层降档**（= 第 1 条诉求） | 后端判据**不动**，只在前端把这类消息降档 / 收拢 | 不解决未读、预算与唤醒污染（只是让它「看着不像发言」）；判据可以放松（宁可少降档、不可误吞真实回复）；可**独立落地**，不依赖判据裁定 |

**裁定判据时必须一并回答的两个约束**（本票只提出，不代答）：

- **误判方向**：判成发言的代价是「多一条旁白消息」（观感 + 一格预算）；判成沉默的代价是「一条真实回复被吞掉」。
  两者不对称，规格倾向后者更严（但这条倾向本身也待用户确认，不由本票代为拍板）。
- **判据的落点唯一性**：本仓既有纪律是「解析只有一个落点」（见 `CONTEXT.md` 的「补全 / 提及」词条与
  「成员面适配接缝」的定义——协作域只认识两个形状）。判据必须落在**一个**位置，不能前端判一遍、后端再判一遍。

### D2｜第 3 条诉求与第 2 条诉求的关系（已定：阶段 3 是阶段 2 的目标态，落点是 D3）

**结构化沉默信号（第 3 条）是第 2 条的干净目标态**，两者是**同一条路线的两个阶段**而不是并列的两件事：

- 第 2 条说「结果要归到 `ignored` 一侧」——这是**结果**；
- 第 3 条说「别猜、让模型说」——这是**判据来源**。

若进到 判据-2（阶段 3），则第 2 条的「可靠判据」问题被**消掉**，而不是被回答：后端不再需要判断
「什么算无实质内容」，它只读一个字段。因此 D1 的裁定与 D3 的落点**必须一起定**：先定判据来源（哪个阶段、
用什么判据），再定它在接缝上的形状。反过来说，阶段 2 的判据可以是**临时**的——只要它的失效模式是显式的
（宁可判成发言，也不吞掉真实回复），并写明它将被阶段 3 取代。

### D3｜⏳ 待定决策点：结构化沉默信号的落点（对现有 `RoundOutcome` 契约的影响）

三条候选路线，均未拍板，各自对既有契约的冲击如下：

| 路线 | 形状 | 对契约的影响 |
| --- | --- | --- |
| **落点-a：`RoundOutcome` 增显式字段**（如「已声明沉默」布尔） | `status` 仍取 `SEAM_STATUSES` 三元（`app/alibot/agent_seam.py:25`），另加一个正交字段 | `SEAM_STATUSES` 与 `round_outcome.status` 的 CHECK 词表（`app/alibot/db.py:143-144`）**都不动**；但要在 `RoundOutcome.__post_init__`（`app/alibot/agent_seam.py:115-121`）加**互斥校验**（声明沉默 且 `messages` 非空 ⇒ 失败），并在落库侧把该字段映射进 `reason` 以便可读 |
| **落点-b：`SEAM_STATUSES` 增第四个词**（如 `silent`） | 沉默成为与 `replied` / `ignored` / `failed` 平级的 status | 冲击三处词表：`SEAM_STATUSES`（`app/alibot/agent_seam.py:25`）、`ROUND_STATUSES` 与 `round_outcome` 的 CHECK（`app/alibot/db.py:45` / `app/alibot/db.py:143-144`）、前端 `OUTCOME_SUMMARY` / `SUMMARY_STATUSES`（`app/alibot/studio/app.js:65-81`）；因为动了库级 CHECK，会牵到 `SCHEMA_VERSION`（`app/alibot/db.py:35`，现为 3）与「不做旧数据迁移」的既有口径（ADR-0004 定的） |
| **落点-c：复用 `ignored`，只把声明事实写进 `reason`** | 零词表变化；「模型声明沉默」与「seam 判为忽略」只在 `reason` 文本上不同 | 契约冲击最小；代价是（i）两者在**取证面不可区分**（要读文本），（ii）`reason` 变成半结构化字段，与「可读 reason」的定位相冲 |

**本票不选。** 定这条时要连带确认：替身（`app/tests/scripted.py` 的 `ScriptedAgentSeam`）与既有
「四种行为固定」的注入面是否需要扩一个行为；以及前端摘要行是否需要多一个 status 的中文说法。

### D4｜⏳ 待定决策点（不阻塞、可最早动工）：呈现层降档的形态（第 1 条诉求的「收拢还是降档」）

**这一项不依赖 D1 / D3 的裁定**，因此可以最早动工；待定的只是它的形态。

约束先摆清：**摘要行的锚点是 `base_seq`（它服务于 `round_outcome` 记录），而旁白是一条 `message`，锚点是 `seq`**
（`app/alibot/studio/app.js:997-1007`：摘要行刻意用 `data-base-seq`、不是消息、不占 `seq`）。所以「把旁白并入那行摘要」
要么跨两个数据面拼装，要么就得放弃「同一锚点」这个既有性质。三条候选：

| 形态 | 做法 | 代价 |
| --- | --- | --- |
| **形态-a：消息级降档，不合并** | 给旁白消息一个同族的轻量呈现（一行、低权重、可展开看 `reason`），仍以消息自己的 `seq` 落位 | 消息流里仍多一行——只是「不像发言」，不减少行数；实现最简单、不跨数据面 |
| **形态-b：并入上一条摘要行** | 把旁白在呈现层收进同一批「没有回应」的摘要行里 | 需要把 `message` 与 `round_outcome` 两个数据面在呈现层对齐；摘要行的 `aria-label` / 计数口径要重新定义（#18 明确写了「它不是消息、不占 seq、不参与数几条消息的统计」） |
| **形态-c：只改标签与视觉权重** | 保留消息行，只把 `msg-tag` 从 `'Agent'`（`app/alibot/studio/app.js:1203`）降成另一种标识（如「（未回应）」），并压视觉权重 | 改动最小；但**「无实质内容」这个判据必须前端自己知道**——与 D1 的「判据落点唯一性」冲突（前端判一遍、后端再判一遍），规格倾向否掉，但留作记录 |

**注意**：形态-c 与本票倾向的「判据落点唯一」相冲，列出来是为了把否掉的理由写清，不是推荐路线。

### D5｜阶段 1（第 4 条诉求）的评估结论与改写方向（已评估，措辞定稿不在本票）

**评估：现行系统提示确实在诱导括注。** 原文（`app/alibot/agent_seam.py:270-274`）：

> 你在一个多成员频道里协作者的身份是「成员」，不是人类。回应纪律：被个人提及（@你的名字）时必须回应；
> 话题明确与你无关、或你没有被点名时，应当保持沉默（**只回一个空字符串之外的简短说明不算回应**）。

三点问题：

1. **自相矛盾**：主句要「保持沉默」，括注却把「空字符串之外的简短说明」定性为「不算回应」——模型要同时满足这两句，
   最省力的解就是**给出一句简短说明**（它确实是「简短说明」，也确实「不算回应」）。
2. **它给了模型一个措辞模板**：括注等于在提示里示范了「简短说明」这种输出形态，而输出形态在 prompt 里出现时
   就是被模仿的对象。
3. **它把「沉默」定义成了对模型的**输出格式要求**（空字符串），而不是对**结论**的要求**；一旦模型的输出通道
   不能真的产出空串（或产出空白），这条纪律就无从遵守，只能退回括注。

**改写方向（方向已定，措辞不在本票 Out of Scope）**：

- 把「沉默」从**输出格式**改成**结论**：沉默 = 本轮不以任何形式产出正文，包括括注、旁白、说明、道歉。
- 让模型有一条**显式的表达通道**表达沉默（即便 D1 最终不选结构化信号，提示里也不能再用「简短说明」作范例）。
- 把「必须回应」的例外与穿透点名（`mention` 必须回应 → 自判忽略按 `failed` 处理，见 `CONTEXT.md` 的「回应判断」与「穿透」）
  的关系写清，避免模型在「必须回应」与「保持沉默」之间找中间态。
- **不再用「回一个空字符串」作为规范措辞**——它把纪律绑死在某个通道的具体行为上。

### 与既有 ADR / 契约的关系（显式指出，不静默绕过）

- **ADR-0001（消息 append-only）**：本票**尊重**，不试图修改历史旁白消息。它的直接后果是「历史降档只能在呈现层做」（D0-c / D4）。
- **「一轮 ↔ 至多一条频道消息」契约**（`CONTEXT.md` 的「轮次」词条 + `RoundOutcome.__post_init__`）：
  本票**尊重并加强**（D0-d）——引入沉默声明后要加互斥校验，不放松上界。
- **#1「回应判断」词条**：「明确无关 ⇒ 应当 `ignored`，这是正常的协议选择而不是失败」——本票与之一致，
  不新增 status 语义；若最终选落点-b（新增 status 词），需要确认它是不是**新语义**（新语义 ⇒ 新 ADR）。
- **⚠️ 可能需要新 ADR 的情形**：若 D1 裁定采 判据-2 **且** D3 裁定采 落点-b（新增 status 词），则「沉默」成为
  轮次结果的**第六种状态**，这会改动 `round_outcome` 的库级 CHECK 与 `SCHEMA_VERSION` 口径，
  属于**跨模块的持久化契约变更**——本票要求实施前先写一条新 ADR（编号从 `0007` 起），说明新 status 词与
  `ignored` 的边界，以及为什么不能在 `reason` 里表达。（本票**不**写这条 ADR：它依赖 D1 / D3 的裁定，现在写等于代替用户拍板。）
- **ADR-0002（预算 ≤ 3）**：本票与之一致——判成沉默的那一轮**不构成一次跳**，是既有口径的自然推论
  （跳的定义是「一条 Agent 消息投递了至少一个唤醒」，没有消息就没有跳），不是对 ADR-0002 的修改。
- **#18 的呈现纪律**：一行摘要、默认折叠、`failed` 直接展开、摘要行不占 `seq` 也不参与「数几条消息」——
  本票沿用（D0-e / D4）。

## Testing Decisions

**接缝：不新开 seam。** 验收走既有的唯一高层接缝
（`发送频道消息 → 后端持久化 → 唤醒 AgentScope agent → 追加回复 → 前端实时呈现`，见 #1「用户已确认的边界」第 1 条），
以及既有的成员面适配接缝（`AgentSeam` / `RoundOutcome`，`CONTEXT.md` 的「成员面适配接缝」词条）。

**好测试的判据（本仓既有口径）**：只测**外部可观察行为**，不测实现细节。据此：

- **该测的**：一次唤醒之后**有没有新的 `message` 行**；`round_outcome` 里那一条的 status 与 `reason` 可读性；
  `target_budget.used` 有没有 +1；未读计数有没有变；前端那条呈现是否仍在**一行**以内且默认折叠。
  这四件事都是「外部行为」，都能从既有只读端点与 `round_outcome` 记录读到。
- **不该测的**：具体的正则 / 措辞表 / 具体的提示词文本。判据一旦被测试固化，就变成了「不许改 prompt」的隐式约束——
  那正是 D1 要避免的。

**测试落点与既有先例**：

- **阶段 1（prompt 纪律）没有可断言的行为测试**：提示是文本，断言它就会把「不许改 prompt」变成隐式约束。
  它的验收是**归因可读**（能在提示里指出那句括注）+ 观测（旁白发生率下降），不是自动化断言。规格把它列为
  阶段 1 的**已知局限**，不当成遗漏。
- **阶段 2 / 3 的后端行为测试**沿用 `app/tests/` 的既有族：用 `app/tests/scripted.py` 的 `ScriptedAgentSeam`
  注入「回应 / 忽略 / 失败 / 延迟」四种固定行为（不联网、零成本）；预算与唤醒面断言参照
  `app/tests/test_bounded_relay.py`，轮次结果可见化参照 `app/tests/test_round_outcome_visibility.py`。
  若阶段 3 需要替身多一个行为，扩展既有替身的**注入面**，而不是新开一个接缝。
- **前端呈现测试**沿用 #18 的用例族（同一批分组事实 + 折叠控件断言），**不新开第二套摘要行实现**；
  阶段 1 的呈现层改动即可用这族用例验。
- **基线与红绿要求（阶段 2 / 3）**：改前的可观察事实是「一条 `kind="agent"` 消息落库 + 一次 agent→agent 跳 + 预算 -1」；
  改后应是「零条新 message 行 + 一条 status 为沉默的轮次结果 + 预算不动」。两者都能用既有接缝断言，
  因此这是一条**能红→绿**的验收，而不是只测呈现。**阶段 1 单独交付时不产生这条红→绿**（数据面无变化），
  这是把它排在最前却不把它当终态的理由。

**本票自身的验证方式**（规格票不跑源码测试）：本票只产出 issue 与文档，验证靠
「Out of Scope 非空且明确」+「待定决策点被显式标注」+「四条代码事实带文件:行号」+「术语与 `CONTEXT.md` 一致」四项自检。

## Out of Scope

- **本票不产出实施票**。本票不拆分实施票、不建立任何 sub-issue 依赖、不指定实施顺序。
- **本票不改任何代码**。`app/` 下的 `.py` / `.js` / `.css` / `.html`、`app/tests/`、`alibot-design-system/`
  一律不动；本票的表达面只有 GitHub issue 与（若有决议时的）`CONTEXT.md` / `docs/adr/`。
- **本票不裁定 D1 / D3 / D4**。阶段 2 的判据、阶段 3 的结构化落点、以及呈现层的形态三项都留给
  「实施前定夺」，本票只交付候选与代价（阶段路线的**顺序**已定，是 coordinator 的裁定）。
- **本票不写 prompt 的最终措辞**。只给改写方向与问题归因（D5）；具体文案留给实施票。
- **不做内容质量评分 / 发言审核**。本票不判断「这条回复有没有价值」——它只处理「Agent 自己交代了沉默」这一种形态。
- **不做历史数据回填 / 迁移**。ADR-0001 之下历史不可改；也没有「批量把历史旁白标成沉默」的路径。
- **不新增消息 kind**。`MESSAGE_KINDS` 不变（D0-b）。
- **不做其它呈现改造**。预算条、轮次结果全览页、按成员筛选 / 搜索 / 排序，仍按 #18 的边界不在范围内。
- **不做多语言 / 多模型措辞适配表**。若最终选 判据-1，维护多语言措辞表也不在本票授权内。
- **不触发任何人类 / 凭证 / 不可逆 live 数据操作**。
