## Problem Statement

我在频道里让 Agent 旁听，或者 @ 了它但这一轮其实没什么可说的。它回了一条消息，正文是：

> （本轮消息与我无关，无需回应）

这条消息和一次真实回复长得一样：占 `seq`、计入未读，且照常唤醒其它 Agent 并消耗预算。它只是把「我不需要说话」当成正文说出来。历史消息 append-only，不能通过编辑或删除修正。

### 已核实的代码事实（基线：#31 合并后的 main `742188b`）

1. 现行 seam 将非空正文作为 `replied`，随后经唯一 Agent 回复落库路径写成 `kind="agent"` 消息；消息写入只校验正文非空，不识别旁白语义（`AgentScopeAgentSeam.run_round`、`Orchestrator._commit_reply`、`Database.append_message`）。
2. 消息种类为 `human` / `agent` / `system`；普通 Agent 消息计入未读，没有单独的旁白消息类型（`MESSAGE_KINDS`、未读查询、Studio `messageNode`）。
3. Agent 消息照常触发后续唤醒；发生 Agent→Agent 实际投递时照常消耗预算（`Orchestrator.notify`、`_spend_jump`）。
4. 既有 `ignored` 轮次结果是不产生待落库回复的正常路径；`round_outcome` 有 status、reason 和 reply sequence 取证面。现状没有旁白 status。

**本路线的已知代价**：D1 选择仅呈现层降档，因此旁白仍是普通消息数据，不会因此停止占 `seq`、计未读、触发唤醒或影响预算。未读与预算污染不是遗漏，明确不在本路线内解决。

## Solution

采用两张垂直实施票：先定稿 prompt 纪律并对旁白消息做保守的消息级轻量呈现；再加入结构化沉默信号，使模型声明的沉默成为独立、可查询的轮次结果。第一张票不改变后端判断或账本事实；第二张票不回写历史。

```text
① prompt 纪律 + 呈现层降档
   更新系统提示最终措辞；旁白仍是原 message / seq / unread / wake / budget 事实
   Studio 仅做保守呈现降档，历史与未来消息均保留原 message 行及 seq

② 结构化沉默信号
   模型显式声明沉默 → seam status="silent"，零条待落库消息
   round_outcome.status="silent"，reason 继续承载可读诊断
   不新增消息 kind；不迁移旧数据
```

- **①单独交付**：提示纪律降低旁白发生率，呈现层使旁白阅读权重更轻。提示是概率性的，不能保证旁白不再发生；D1 不改后端判据，所以 unread、唤醒与预算仍按普通 Agent message 计算。
- **②单独交付**：结构化信号将“模型明确声明沉默”从既有 `ignored` 结果区分出来。`silent` 必须与非空 `messages` 互斥。
- **依赖边**：②（#58）blocked by ①（#57）。没有独立的“seam 文本判据”票，不增第三张票或额外治理结构。

## Implementation Decisions

### 术语（按规格原案落入 `CONTEXT.md`）

- **沉默 (Silence)**：用户可见语义，指一轮没有以普通正文回应。子票①只调整旁白提示与呈现，不重新判定后端事实；子票②中模型经结构化通道显式声明的沉默持久化为 `silent`。
- **旁白式交代 (Silent Narration)**：反面词，写入 `CONTEXT.md` 的 `_Avoid_`。定义：Agent 把「我不需要说话」当成正文说出来，仍是一条真实 `kind="agent"` 消息，会占 `seq` 并按既有规则参与未读、唤醒与预算。`_Avoid_`：沉默说明、空回应、括注消息。
- **`silent`**：轮次结果状态，表示模型经结构化通道明确声明本轮沉默；不是消息 kind，也不是失败。它与 `ignored` 的边界 inline 写入 `CONTEXT.md`，详见 D3 与 ADR-0008。

### 已定的基础约束

- **D0-a｜两张垂直实施票**：① prompt 纪律改写 + 呈现层降档；② 结构化信号 + `RoundOutcome` 互斥校验及持久化契约。② blocked by ①。
- **D0-b｜消息 kind 不变**：不新增 `MESSAGE_KINDS`；消息仍为 `human` / `agent` / `system`。`silent` 是轮次结果状态。
- **D0-c｜历史 append-only**：历史旁白不可回填、编辑或删除；只在呈现层降档。提示改写不承诺未来旁白绝不出现。
- **D0-d｜轮次消息互斥**：保留“一轮至多一条 target 消息”；status=`silent` 时必须零条待落库消息。
- **D0-e｜沿用 #18 轻量交互**：一行、低权重、可展开查看关联 `reason`，键盘可操作；旁白仍是消息，不挪用非消息摘要行语义。

### D1｜阶段 2 最小判据：判据-4（只做呈现层降档）

| 候选 | 做法 | 代价 / 风险 |
| --- | --- | --- |
| **判据-1：seam 层文本启发式** | 适配层以正则 / 白名单匹配括注或固定说法 | 换模型、语言或措辞会失效；会误伤真实短回复；把猜测固化成后端正确性判据 |
| **判据-2：模型结构化声明** | 模型输出显式沉默字段，后端读字段 | 需要 provider 支持并扩展轮次结果、替身与测试；属于结构化阶段 |
| **判据-3：空正文 + 哨兵值** | 约定 `NO_REPLY` 等哨兵表示沉默 | 仍依赖模型遵守格式，哨兵也可能泄漏进正文 |
| **判据-4：只做呈现层降档** | 后端判据不动，仅对旁白消息做呈现降档 | 不改变未读、唤醒或预算事实；必须保守，不能误吞真实回复 |

**结论：选择判据-4。** 子票①仅做呈现层降档，后端判据不动，不引入后端正则、措辞表或哨兵。失效方向可放松：宁可少降档，不可误吞真实回复。旁白仍可能占 `seq`、计未读、触发唤醒并消耗预算；**未读与预算污染是本路线的已知代价，不在本路线内解决**，不是遗漏。

**裁定来源：用户 2026-10-16 定夺；裁定方式：人定。**

### D2｜阶段与诉求关系

D1 判据-4 是呈现决定，不把旁白改成 `ignored`，也没有独立的后端 seam 判据可拆成一票。结构化信号是另一项数据契约演进：显式 `silent` 区分模型声明与既有 `ignored`。因此恰拆两票：第一票合并 prompt 与呈现；第二票实施结构化信号及持久化契约。

### D3｜结构化沉默信号的落点：落点-b

| 路线 | 形状 | 对契约的影响 |
| --- | --- | --- |
| **落点-a：`RoundOutcome` 增显式字段** | 保持原 status 词表，增加正交布尔字段 | status CHECK 不变；仍需互斥校验，并定义该字段的外部表达与 reason 映射 |
| **落点-b：`SEAM_STATUSES` 增第四个词 `silent`** | `silent` 与 `replied` / `ignored` / `failed` 平级 | 扩展 seam、库级 `ROUND_STATUSES` / `round_outcome.status` CHECK、Studio `OUTCOME_SUMMARY` / `SUMMARY_STATUSES` 中文说法；更新 `SCHEMA_VERSION`，按 ADR-0004 不做旧数据迁移 |
| **落点-c：复用 `ignored`，只写入 `reason`** | 不扩状态词表，以文本说明声明来源 | `reason` 变成半结构化协议；机器无法稳定区分两种事实，取证依赖自然语言 |

**结论：选择落点-b。** 新增 `SEAM_STATUSES` 第四个词 `silent`，并在持久化及前端状态词表同步纳入。`ignored` 表示既有 seam 的正常自判忽略；`silent` 专指模型经结构化通道明确声明沉默。`RoundOutcome(status="silent")` 与非空 `messages` 互斥。`reason` 是可读诊断文本，允许自由措辞、没有库级词表约束，无法稳定查询或强校验；若把声明塞入 `reason`，会混淆状态并使取证依赖文本，因此不能替代独立 status。

基线 `SCHEMA_VERSION` 为 6；实现落点-b 时需随库级 CHECK 变更递增版本。按 ADR-0004，不为既有库增加旧数据迁移。`docs/adr/` 当前最大编号为 0007，本规格新增 **ADR-0008** 记录该跨模块持久化契约。

**裁定来源：用户 2026-10-16 定夺；裁定方式：人定。**

### D4｜呈现层降档形态：形态-a（消息级降档，不合并）

| 形态 | 做法 | 代价 |
| --- | --- | --- |
| **形态-a：消息级降档，不合并** | 旁白保留自己的 `seq` 与消息行，以同族轻量形式一行、低权重、可展开看关联 `reason` | 仍占一行，但不跨数据面拼装 |
| **形态-b：并入上一条摘要行** | 把旁白并入 `round_outcome` 摘要 | 必须跨 `message` / `round_outcome` 对齐，并重定摘要的消息计数与无障碍语义 |
| **形态-c：只改 `msg-tag`** | 只改标签及视觉权重 | **明确否决**：与「判据落点唯一」冲突，不能表达消息级轻量内容及其可展开理由 |

**结论：选择形态-a。** 历史与未来旁白都按自身 `seq` 保留 message 行，不并入 `round_outcome` 摘要；只给同族轻量呈现并展开查看关联 `reason`，不跨数据面拼装。形态-c 已否决，原因是与判据落点唯一冲突。

**裁定来源：用户 2026-10-16 定夺；裁定方式：人定。**

### D5｜prompt 纪律评估与措辞范围

现行提示的“保持沉默（只回一个空字符串之外的简短说明不算回应）”语义自相矛盾：主句要求沉默，括注却示范简短说明可作为合规形态。改写方向是把沉默定义为不产出正文（包括括注、旁白、说明、道歉），不再要求回空字符串，并写清被点名必须回应与自判忽略的边界。**最终提示措辞由子票①定稿**；本规格不代写生产提示文本。

### 与既有 ADR / 契约的关系

- **ADR-0001（消息 append-only）**：尊重；历史旁白只改呈现，不回填、编辑或删除。
- **ADR-0002（回应预算）**：子票①不改唤醒或预算语义；D1 下未读、唤醒及预算污染保留为已知代价。
- **ADR-0004（target / schema）**：落点-b 修改 status CHECK，递增 `SCHEMA_VERSION`，不做旧数据迁移；ADR-0008 记录新状态契约。
- **#18 呈现纪律**：沿用轻量、一行、可展开原则，但旁白自身仍是消息，不并入 `round_outcome` 摘要。

复核 ADR-0001、0002、0004、0007 后，未发现用户裁定与现有 ADR / 契约直接矛盾；新增 ADR-0008 记录新增状态及其边界。

## Testing Decisions

**接缝：不新开 seam。** 沿用既有高层接缝（发消息 → 持久化 → 唤醒 → Agent 回复 → 前端呈现）与成员面适配接缝（`AgentSeam` / `RoundOutcome`）。

只测外部可观察行为，不测实现细节：

- 子票①断言历史与未来旁白仍以原消息和原 `seq` 存在，并以一行、低权重、可展开的形态呈现；普通实质回复保持普通呈现。具体 prompt 文本以人工规格核对为主，不固化为行为测试。
- 子票①不应断言未读、唤醒或预算污染已消失；它们仍按普通 Agent message 的既有契约计算。
- 子票②通过既有脚本化 seam 覆盖 `silent`、`ignored`、`replied`、`failed`；断言 `silent` 有一条结果、无回复 message、`reason` 可读，且 `silent` 与非空 `messages` 被拒绝。
- 子票②核对库级 status CHECK、`SCHEMA_VERSION` 与前端 `OUTCOME_SUMMARY` / `SUMMARY_STATUSES` 一致；不执行旧数据迁移。
- 前端测试沿用 #18 用例族，覆盖一行、展开、键盘与可访问性，不新增摘要实现或跨数据面拼装。

本规格票不跑源码测试、双轴 code-review 或 G-impl；只核对模板、seam 数量、决策结论、术语结构与 tracker 回执。
