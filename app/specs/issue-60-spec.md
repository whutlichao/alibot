# Issue #60 规格正本（正文逐字留档）

> 更新时间：2026-10-16 ｜ 仓库：whutlichao/alibot ｜ 正本：https://github.com/whutlichao/alibot/issues/60

Part of #1（首版规格锚点）。

**票型**：规格正本 ｜ **门禁**：G-spec + G-tickets（ADR / `CONTEXT.md` 按规划门禁一并核）｜ **本票不跑**：源码测试、lint/typecheck、双轴 code-review —— 本票改动全部落在 `app/specs/**`、`CONTEXT.md`、`docs/adr/**` 与 tracker 写操作，没有源码行为改动。

本票是**第三轮工作台对齐**的规格正本，与 #22 / #23（第二版能力扩展）、#31（回应预算）、#35（沉默语义）平级、互不修改。它只定范围、证据、术语、ADR 与拆票，不实施生产代码或测试。

## Problem Statement

工作台已经两轮对齐过设计系统原型（#42 把任务面板搬回主线页签、左栏回三段；#44 把任务线程搬进 dock、看板回 236px 列宽与 `.seg`/`.filter-chip` 工具栏）。那两轮是**只对齐已实现能力的位置与结构**（上一轮的人定 U1），显式把「原型有、studio 从未实现」的面全部排除。

本轮用户改口：点名了六面（搜索、私信、语言切换 i18n、Agent 详情与编辑、新建任务后 Agent 主动认领、聊天框内直接创建任务），并追加四面（设置弹窗、提醒 reminders、composer 工具行、成员弹窗、移动端抽屉壳）。其中三条已被用户直接人定，不留给本票重新裁定：

1. 交付终点不停在票据：**收敛 → 规格 → 拆票 → 逐票实施并自动合并到 main**。
2. 「语言切换」是**完整 i18n、全量双语**（简体中文 / English），不是只加一个下拉框。
3. 「新建任务后 Agent 主动认领」是**真做行为**（Agent 配置开关 + 编排认领），不是只做界面开关。

这些面之所以到第三轮还空着，根因不是工作量，而是**上一轮的裁定理由**：原型里有一批面根本没有数据面，照抄即重演「原型是假象」。本轮必须先逐面取证「原型拥有什么 / studio 实现了什么 / 后端有没有真数据面」，再决定每一面是「对齐」还是「新建能力」，而不是先画界面再补数据。

因此本票的第一交付物不是界面清单，而是**逐面核实表**：每条给 `file:line`、选择器或端点级证据，并显式标注该面在原型里是**有真数据面**还是**写死的假数据**。这一列直接决定后续每张实施票能不能做、以及做的是对齐还是能力建设。

### 已核实的代码事实（基线：`main` = `fb36dfa2`）

1. **后端没有任何设置面**：路由全表没有 settings / preference / locale 端点（`app/alibot/api.py:258-460`），库里没有设置表（`app/alibot/db.py:118-264` 的十张表）。语言偏好、主题、消息密度、提醒四者都无处落库。
2. **Agent 配置只读不写**：`GET /api/agents`、`GET /api/agents/{id}`、`/status`、`/api/member-statuses` 都在（`api.py:411/425/429/433`），配置字段 `role` / `model_id` / `system_prompt` / `enabled` 落 `agent_config` 表（`db.py:223-232`）；**没有** `PATCH /api/agents/{id}`，因此「编辑配置」与「暂停」两条动作今天都没有写路径。
3. **Agent 运行观测无数据源**：`RUNTIME` / `LOGS` 是原型里的种子常量（`alibot-design-system/alibot-app.html:967-973`），概览页的「本周用量 / Token 消耗 / 上下文用量」是写进 DOM 的 Susan 数值；`grep -rniE 'token|usage|runtime|log' app/alibot/*.py` 无业务命中，seam 不回传 provider usage，也没有后端日志落库面。
4. **认领不存在**：`grep -rniE 'claim|认领' app/alibot/*.py` 只命中状态标签（`db.py:67` 的 `todo: 待认领`）；`db.py` 的 `update_task_assignee` 现规则是「owner 改派 = 开人类世代 + 重置预算 + 唤醒受派者；Agent 改派 = 一次 agent→agent 跳」，且**直接拒绝** Agent 认领未指派任务（`previous_id != actor_member_id` 即报错）。
5. **搜索只搜消息**：`GET /api/search`（`api.py:266`）→ `Database.search_messages`（`db.py:1414`），SQL 是 `SEARCH_ALL_HITS_SQL` / `SEARCH_TARGET_HITS_SQL`，只查 `message` 且排除 `kind='system'`；原型的三类命中里任务与 Agent 两类**没有**后端来源。
6. **附件不存在**：没有附件表、端点或文件存储；原型自己的附件按钮也只是 `toast('附件选择器（原型占位）')`（`alibot-app.html:1799`）。
7. **`SCHEMA_VERSION = 6`**（`db.py:41`），`round_outcome.status` 的库级 CHECK 仍是五个词（`db.py:244-258`）——即 #35 的 `silent` / ADR-0008 尚未实施，本票新增 schema 改动时必须把这条先后关系写清。

### C. 本表口径说明

- 「有真数据面」不等于「studio 已实现」：面 2（私信）两者都满足，面 9 的 @提及也是；面 4 的配置面是「读有、写无」，故标注为部分。
- 「无数据面」不等于「不做」：用户已人定的三项（i18n、主动认领、设置弹窗）里有两项本身就无数据面，本轮按**能力新建**处理，而不是照抄原型的假界面。
- 原型的 `mark()` 只包裹**第一处**命中（`alibot-app.html:1489-1494`），而本仓既有契约更强：`CONTEXT.md` **高亮区间** 明写「区间标出**全部**命中」，且命中判定唯一落点在后端（`db.py:1414`）。本轮**沿用仓库契约**，不因原型更弱而回退。

## Solution

把 11 个面按三类处置落成**一票一交付**的实施序列：**有真数据面 → 对齐**（私信、@提及、搜索的消息命中、成员名册）；**无数据面 → 能力新建**（i18n、设置偏好、提醒、附件、Agent 详情与编辑、主动认领）；**用户未点名 → 显式排除并写明理由**（看板拖拽、pin-strip、消息 hover 工具条与 reaction、`dedupe` / `backfill` 两个原型开关、设计系统包内的 locale 声明）。三类处置的依据都在上面的逐面核实表里，没有一条凭观感。

承重纵切是 **i18n 地基票**：它先立「词条 + 语言偏好」这套契约，此后每一张 UI 票都在两套词条里加自己的文案。这是本轮唯一一条把「顺序」写进依赖边的原因——不是因为怕冲突，而是因为双语覆盖率必须由构造保证，不能靠事后补扫。其余票之间只有两处真实顺序：**主动认领**必须等 **Agent 配置写路径**（开关的落点在那里），**附件**必须等 **composer 工具行**（按钮位在那里）。

```text
#60 规格正本（本票）
├─ ① i18n 地基：词条机制 + 工作区设置面 + 前端全量双语 + 设置弹窗（语言 / 消息密度）   ← 无 blocker
│   ├─ ② 后端可见文案双语（HTTP 错误 / system 消息 / 轮次与可用性 reason / 远端告知）
│   └─ ⑪ 深色 token 族 + 主题三档（浅色 / 深色 / 跟随系统）
├─ ③ 搜索面：后端三类命中 + 主线搜索视图 + 四 facets + ⌘K 命令面板
├─ ④ Agent 详情与编辑：dock 第三形态 + PATCH /api/agents/{id} + 概览 / 运行时 / 暂停
│   └─ ⑤ Agent 主动认领：auto_claim 配置 + 编排认领 + 每任务一次的开世代
├─ ⑥ composer 工具行：@提及 落位 + 作为任务发送

├─ ⑨ 成员名册弹窗
└─ ⑩ 移动端抽屉壳（≤900px）

```

- **①单独交付**：切到 English 后主线界面（频道 / 私信 / 任务 / 看板 / 线程 / 弹窗 / 空态 / 无障碍标签）全部英文，刷新后保持，`<html lang>` 同步；设置弹窗同时交付语言与消息密度两个真档位。
- **②单独交付**：新落库的 `system` 消息、HTTP 错误文案、轮次结果与可用性 reason、远端数据流告知文案按当前语言产出；**历史消息保持写入时的语言**（append-only，不回填）。
- **③单独交付**：`GET /api/search` 一类命中扩为三类，前端搜索成为主线视图且有四档 facet 与命中高亮；`⌘K` 打开命令面板。
- **④单独交付**：点 Agent 打开详情 dock（概览 + 运行时两个页签），可暂停、可编辑配置并读回。
- **⑤单独交付**：开启 `auto_claim` 的 Agent 在频道内新建任务后由编排认领并唤醒，认领结果在任务卡片与线程上可读。
- **⑥单独交付**：composer 工具行三个按钮按原型落位（附件按钮随 ⑦ 接线），`@提及` 走既有补全，「作为任务发送」把正文预填进既有新建任务弹窗。
- **⑦单独交付**：先上传拿标识、发送时绑定，消息渲染出附件；未绑定的上传只是草稿。
- **⑧单独交付**：rail 提醒入口 + 弹窗增删 + 重启后仍在。
- **⑨单独交付**：频道成员只读名册弹窗。
- **⑩单独交付**：≤900px 抽屉外壳（topbar / rail 抽屉 / scrim / dock 抽屉 / 看板单列）。
- **⑪单独交付**：深色 token 族（包内基础族 + app 层三个产品角色族的深色取值）+ 主题三档（浅色 / 深色 / 跟随系统）+ 设置弹窗第三档接线；验收在真实浏览器里看对比度与三档切换。

## User Stories

### A. 搜索面（面 1）

1. 作为本机用户，我想在搜索里按「全部 / 消息 / 任务 / Agent」四档切换，这样我不用在结果里自己分辨命中类型。
2. 作为本机用户，我想搜到**任务**（标题命中）与 **Agent**（名字 / 角色命中），而不只是消息。
3. 作为本机用户，我想命中片段里的**全部**命中位置都被高亮，而不只是第一处。
4. 作为本机用户，我想搜索是主线视图（占消息流那块位置）而不是盖住界面的弹层，这样结果能读满一列。
5. 作为本机用户，我想用 `⌘K` / `Ctrl+K` 打开命令面板，用 `ESC` 关掉它。
6. 作为本机用户，我想命令面板的命令集是**真实存在的能力**（跳转 / 新建 / 切换详情面板 / 当前频道），不出现指向不存在的快捷提示。
7. 作为本机用户，我想命中判定始终由后端给出，前端不自己决定「算不算命中」。

### B. 私信（面 2）

8. 作为本机用户，我想私信继续留在左栏中段、标题带 `@`，且私信里不出现任务页签（这是上一轮已交付的事实，本轮不回归）。
9. 作为本机用户，我想私信里也能用与频道一样的 composer（含工具行），因为「发消息」是同一件事。

### C. 语言切换与 i18n（面 3）

10. 作为本机用户，我想在设置里切换**简体中文 / English**，并且**整个界面**都跟着变，而不是只有下拉框变。
11. 作为本机用户，我想刷新页面、重启后端后语言选择仍然生效。
12. 作为本机用户，我想 `<html lang>` 随语言切换，让浏览器与辅助技术知道当前语言。
13. 作为本机用户，我想新产生的系统消息、错误提示、轮次与状态原因按我当前的语言产出。
14. 作为本机用户，我想历史消息保持它写入时的语言，不被回填改写（append-only 是取证面）。
15. 作为实现者，我想文案只有两个落点：**结构化状态**由前端词条渲染，**后端生成的自然语言**由后端按当前语言渲染，不出现第三个落点。

### D. Agent 详情与编辑（面 4）

16. 作为本机用户，我想点左栏或成员面板里的 Agent 就能看到它的详情。
17. 作为本机用户，我想在概览里看到有真实来源的事实（状态点、模型标识、所属频道数、参与过的轮次数与其结果），而不是写死的占位数值。
18. 作为本机用户，我想在运行时页签里看到 `agent_config` 里**真实存在**的字段（模型标识、角色、系统提示、启用状态、远端数据流告知状态），而不是原型编出来的内存 / 延迟 / 工具权限。
19. 作为本机用户，我想能编辑并保存 Agent 的显示名、角色、模型标识、系统提示与启用状态，并读回保存结果。
20. 作为本机用户，我想「暂停」是一个真实动作（落库并可读回），而不是只弹一个提示。
21. 作为本机用户，我想知道暂停的边界：暂停后它不产出回复、状态点为未启用，但仍会被唤醒并留下一条可读原因的失败轮次结果。
22. 作为实现者，我想配置写入只有一个落点（`PATCH /api/agents/{id}`），`model_id` 沿用与创建同一套校验与远端数据流告知。

### E. 新建任务后 Agent 主动认领（面 5）

23. 作为本机用户，我想在 Agent 配置里打开「自动认领任务」，让它自己接手新建的任务。

### F. 聊天框内创建任务（面 6）

28. 作为本机用户，我想在 composer 里写完一段话后点「作为任务发送」，把它变成任务，而不用重新复制文字。

### G. 设置弹窗（面 7）

### H. 提醒 reminders（面 8）

32. 作为本机用户，我想从 rail 打开提醒、看到列表与空态，并新增 / 删除一条提醒。

## Implementation Decisions

### 1. 事实基础

本规格的全部事实基线是上面的**逐面核实表**：11 个面各自的「原型证据 / studio 现状 / 后端数据面 / 处置」。表里每一格都有 `file:line` 或端点级证据，没有一格来自记忆或观感。基线与取证时点：`main` = `fb36dfa2`，2026-10-16。

### 2. 每面的交付契约

- **面 1 搜索**：`GET /api/search` 的命中来源扩为三类（消息 / 任务 / Agent），facets 是**后端过滤参数**；前端把搜索从**弹层**改为**主线视图**，四档 facet + 全部命中位置的 `<mark>`；`⌘K` / `Ctrl+K` 打开命令面板、`ESC` 关闭。命令集见 D10（只呈现真绑定的快捷键）。**沿用** `CONTEXT.md` **搜索命中** / **高亮区间** 的既有纪律：判定在后端，前端不判定。见 ADR-0013。
- **面 2 私信**：**不新增**。已对齐（#42）。本轮的唯一触及是 composer 工具行（面 9）同样出现在私信的 composer 上。
- **面 3 i18n**：完整双语（简体中文 / English），二层机制 + 词条落点 + 语言偏好持久化 + `<html lang>` 同步；切换入口在设置弹窗。机制与冲突处置见 ADR-0009。
- **面 4 Agent 详情与编辑**：dock 新增**第三形态**（Agent 详情），含「概览」与「运行时」两个页签。**概览**呈现有真实来源的事实：当前状态点、订阅频道数、消息处理数、完成任务数、成功率（后三者由既有 `round_outcome` 与任务行推导），加「暂停 / 编辑配置」两个真动作。**运行时**页签只呈现 `agent_config` 里真实存在的字段（模型标识与 `provider` / `is_remote` / 远端数据流告知状态、角色、系统提示、启用），**不**呈现原型的内存 / 延迟 / 工具权限 / 温度。暂停与编辑配置**做实**：新增 `PATCH /api/agents/{id}`，见 ADR-0011。**不做**日志页签、Token 消耗与上下文用量（D24、q3）。
- **面 5 主动认领**：Agent 配置新增「自动认领任务」开关；任务创建后由**编排**裁决并完成认领（落既有 `system` 记录 + 唤醒认领者 + 认领者进入该任务的 **target 成员**），不让模型自己改数据库。预算语义按 q4：**认领不是跳**，但**首次认领开该 task target 的世代并重置预算用量，每张任务至多一次**。见 ADR-0010。
- **面 6 会话内建任务**：composer 工具行的「作为任务发送」按 D6：打开既有新建任务弹窗并预填正文为标题、当前频道预选。
- **面 7 设置弹窗**：rail 入口 + 弹窗，三个字段全部**做实**：语言（面 3）、消息密度（CSS 档位，立刻生效并持久化）、主题（浅色 / 深色 / 跟随系统）。语言与消息密度随 i18n 地基票交付；**主题需要新增深色 token 族**，作为独立实施票（q1），其写面扩到 `alibot-design-system/**`。
- **面 8 提醒**：rail 入口 + `#reminderDot` 指示点 + 弹窗（列表 / 空态 / 新增 / 删除），数据面归属见 ADR-0012。
- **面 9 composer 工具行**：按原型顺序落位三按钮（附件 → @提及 → 作为任务发送 → 分隔 → 提示 → 发送）；`@提及` 复用既有补全；附件真上传（面 9 与面 6 的两个按钮分属两张票，见拆票）。附件契约见 ADR-0014。
- **面 10 成员名册弹窗**：频道成员的**只读全名单**（含 owner，带状态点，动作只有关闭）。术语处置见 D9。
- **面 11 移动端抽屉壳**：≤900px 的 `.mobile-topbar` / `.rail` 离屏抽屉（`.is-open`）/ `.rail-scrim` 收起 / `.dock` 右侧抽屉 / 看板单列；类名与断点照原型与切片（D11）。

### 3. 词条与术语处置

- **新增词条**（`CONTEXT.md` `## Language`，沿用「含义 + `_Avoid_`」格式）：
  - **词条 (String Catalog)**：界面上按语言取值的文案集合，每条有稳定键与参数位；正本是仓库里的源文案（简体中文），英文是同一集合的第二语言取值。_Avoid_：翻译文件（会被读成一份可独立漂移的副本）、i18n 配置（那是机制不是集合）。
  - **语言偏好 (Locale Preference)**：工作台当前的界面语言与后端产出文案语言的**同一个**取值。_Avoid_：界面语言（会被读成只影响前端）、浏览器语言（那是环境信号，不是本仓的取值）。
  - **成员名册 (Member Roster)**：某频道成员的**只读**全名单（含 owner 与状态点）。它回答「这个频道里有谁」，不提供加入 / 未加入的管理动作（那是**成员面板**）。_Avoid_：成员详情弹窗（那是**成员面板**词条 `_Avoid_` 里禁的旧叫法，指把面板说成弹窗）。
  - **附件 (Attachment)**：随消息落库的**文件对象**（元数据落库、字节落本机数据目录），上传后不可改、与消息同口径不可删，不进搜索与成员面。_Avoid_：文件（未指明它挂在消息上、也未必是业务对象）；上传件（只描述过程）。
  - **提醒 (Reminder)**：本机用户给自己设的一条**时间 + 文本**备忘（可关联频道），是后端持有的对象而不是浏览器里的临时状态。_Avoid_：通知、闹钟（前者的推送语义本仓没有，后者只描述时间）；待办（那是**任务**）。
  - **任务命中 / Agent 命中 (Task Hit / Agent Hit)**：搜索的两类非消息结果——任务命中以**任务标题**为命中本体，Agent 命中以**显示名与角色**为命中本体；两者与**搜索命中**同级，且和它一样由后端判定。_Avoid_：搜索结果（那是呈现，不是命中本身）。
- **改写既有词条**：`成员面板` 的 `_Avoid_` 原文含「成员详情弹窗（它现在是面板，不是弹窗）」；本轮把该禁令**收窄**为指向**成员名册**的边界说明（面板 = 管理动作面，名册 = 只读全名单），避免同一句话既禁弹窗、又无法承载用户点名的面。
- **改写既有词条**：`搜索命中` 末尾 inline 说明三类命中的关系（消息命中是既有形状，任务 / Agent 命中是同级新增），并把「命中判定在后端」这条纪律重申为三类的共同约束。
- **不新增**：`跳` / `回应预算` / `预算耗尽` / `人类世代` / `轮次结果` 的既有定义不动（认领与它们的关系写在 ADR-0010，而不是改写词条）。

### 4. ADR 清单与与既有 ADR 的关系

| 新 ADR | 决策 | 与既有 ADR 的关系 |
| --- | --- | --- |
| `docs/adr/0009-i18n-…` | i18n 二层机制与语言偏好落点 | 与 ADR-0007 同族：人类面可以写「配置类」的取值（语言偏好），但**不得**写用量类事实（`target_budget.used`）。不改 ADR-0007 |
| `docs/adr/0010-agent-…` | Agent 自动认领与 ADR-0005 的关系 | **应用并收窄** ADR-0005 的动作表：认领是**编排发起的指派动作**，不是「Agent 转派给别人」那一格；ADR-0005 原文不改，边界写在 ADR-0010 |
| `docs/adr/0011-agent-config-write-path-…` | `PATCH /api/agents/{id}` 与「暂停」的语义 | 与 ADR-0003 一致（配置写路径属于**人类面**，Agent 仍不经 HTTP）；不改 ADR-0003 |
| `docs/adr/0012-…` | 提醒是后端对象 | 应用 `CONTEXT.md` **工作台**「业务状态的唯一正本是后端；前端不持正本」，与原型用 `localStorage` 的做法**显式分叉**并写明理由 |
| `docs/adr/0013-search-hits-extend-to-three-types.md` | 搜索命中扩为三类、判定仍唯一落在后端 | **扩展** `CONTEXT.md` **搜索命中** 的范围而不是推翻它；不改任何既有 ADR |
| `docs/adr/0014-attachments-are-separate-objects-in-the-data-directory.md` | 附件是独立对象、字节落数据目录 | 与 ADR-0001（消息 append-only）一致：附件随消息创建时绑定，不提供删除路径；与 ADR-0003 一致：附件不进成员面 |

- **每一处与既有 ADR 的关系都显式登记**，没有静默覆盖。上面表格就是处置清单；与「用户裁定」冲突的地方（原型用 `localStorage`、原型只有占位 toast、原型只有假观测值）都在 ADR 的正文里写明**为什么与原型分叉**。
- **主题不由 `docs/adr/` 记录**：深色 token 族是**设计系统包**内的决策（token 族与档位规则属包的职责），其决策写进**包内自己的 ADR 编号空间**（由该实施票落笔，不占 `docs/adr/` 的号；这一条是 q1 授权里明确的）。`docs/adr/` 因此保持 0009–0014 连续。
- **设计系统包内的文档冲突**：`alibot-design-system/SKILL.md:145` 与 `DESIGN.md:269` 声明「UI locale is Simplified Chinese」；「全量双语」使这句话不再完整。处置：该声明约束的是**源文案的语言与语气**（简体中文仍是源语言，英文与它同 voice、同样保留品牌名 / 代码 / 模型标识），i18n 是 **app 层的叠加层**；包内那句声明的修订**不在本轮授权内**（q1 的扩面是为深色 token 族），因此**登记冲突 + 处置 + 不做静默覆盖**，见 Out of Scope。

### 5. 拆票与依赖

**粒度原则**：一票 = 一个用户可观察的能力（不是「一层」）。因此不出现「先建表、再建端点、再做界面」的水平切分。

**依赖边只有四处是真实的**：① i18n 地基（后续 UI 票都要在两份词条里加文案，见 D16）；① → ⑪ 主题（主题档位落在地基票建立的工作区设置面上）；④ Agent 配置写路径 → ⑤ 主动认领（开关的落点在配置写路径里）；⑥ composer 工具行 → ⑦ 附件（按钮位与消息创建入口在那里）。其余票之间没有顺序依赖，可以并行。

**票数与依赖顺序的理由**（用户要求写明）：11 个面里，**私信**已对齐（不立票）；**i18n** 因验收面不同拆成前端 / 后端两张票；**设置弹窗**的第三个字段（主题）因要新增深色 token 族而独立成票；**composer 工具行的三个按钮**按「数据面是否已经存在」拆成两张（`@提及` 与「作为任务发送」复用既有端点；附件要新建存储面）；其余每面一票——合计 **11 张实施票**，另加 **1 张 backlog 入口票**（日志数据面，人定不做本体但要求记入口）。票数不是按文件数或按人数定的，是按「可独立验收的能力」定的，11 张里没有一张是另一张的「前半层」。

## Testing Decisions

**接缝不新开。** 后端行为沿用 `app/tests/` 的 HTTP 黑盒接缝（`create_app` + 每条用例独立 `tmp_path` 数据目录 + `tests/scripted.py` 的脚本化 Agent 替身 + 手动调度器），前端 DOM 行为沿用 `node --test app/tests/search_ui.test.cjs` 的既有接缝（`app/README.md:226` 已登记）。规格票本身不运行任何测试。

只断言**外部可观察行为**，不测实现细节：

- **i18n 前端票**：断言切换语言后同一批界面文案的**取值**变化（按词条键取两套值并逐个比对）、`<html lang>` 同步、刷新 / 重启后偏好仍在；不把某一句具体译文写死成契约（措辞可变），只断言「两份词条覆盖同一键集、无落单键」。
- **i18n 后端票**：断言同一动作在两种语言下产出的 `system` 消息 / 错误 message / `reason` 取值不同，且 **HTTP 错误仍带机器可读的 `code` 与 `fields`**（正文可译、代码不可译）；断言历史消息不回填（改语言后旧消息正文逐字不变）。
- **搜索票**：断言三类命中各自能被查到、facet 过滤只返回该类、**全部**命中位置都有区间、`system` 消息不参与命中；断言前端不自行判定（不出现「后端未给区间而前端仍高亮」的路径）。
- **Agent 详情与编辑票**：断言配置读回、非法 `model_id` 整体拒绝且不部分写入、`enabled=0` 后状态点为未启用且 `enabled_reason` 可读、远端 provider 的模型标识触发远端数据流告知的既有语义；断言配置变更**不**落消息、不唤醒、不消耗预算。
- **主动认领票**：用脚本化替身固定「不回应 / 回应」两种行为，断言任务创建后在开关开启且可用时被认领、指派者与状态可读、该 Agent 进入任务成员面、未开启开关时不认领；断言认领只发生一次（不重复指派）。
- **附件票**：断言上传后未绑定不出现在消息里、发送时绑定与消息落库同一事务（消息落库失败则不留绑定）、附件随消息读出可下载、**没有**删除端点；断言字节落在数据目录而不是库里。
- **composer 工具行票**：断言三按钮存在与顺序、`@提及` 追加 `@` 并聚焦、既有补全候选集不变（仍只列当前 target 的 Agent 成员）、「作为任务发送」预填正文且创建后落在当前频道。
- **设置 / 提醒票**：断言三个档位读写与重启后一致；提醒增删与空态、指示点只在有提醒时出现。
- **成员名册票 / 移动端票**：断言名册内容与后端成员表一致（含 owner）；窄屏下的状态类与可交互（抽屉开合、scrim 收起）在真实浏览器里验收（`ego-browser` 实测，与上一轮 UI 票同一做法）。
- 每张 UI 票都追加 D16 的双语验收：本票新增的用户可见文案在两份词条里都存在。

## Out of Scope

**本票自身的边界**

- 本票不改生产代码或测试：`app/alibot/**`、`app/tests/**` 一律不动；只写 `app/specs/**`、`CONTEXT.md`、`docs/adr/**` 与 tracker 写操作。本票也不实施任何实施票的内容。
- 不修改 #1 / #22 / #23 / #31 / #35 的票面与授权范围；#31 的三张实施票（#53/#54/#55）与 #35 的两张（#57/#58）各有自己的正本，本票只登记**与它们的协调事实**（`SCHEMA_VERSION` 先后，见 D13）。
- 不触发凭证、付费、人类审批或不可逆 live 数据操作；本票不运行真实模型。

**用户本轮未点名、且明确排除的原型缺失面**（排除同样要写明理由）

- **看板拖拽**：原型有拖拽状态机与三态落点（切片 `alibot-design-system/screens/task-board.html:8-20` 逐字给出 `TRANSITIONS` 与 `.drag-over` / `.invalid-over` / `.dragging`），studio 的卡片没有 `draggable`、没有 drag 事件（`app/alibot/studio/app.js:738` 的注释写「拖拽属 #26」，而 #26 已关闭）。**本轮不做**：用户本轮点名的六面里没有它，它属于任务写路径的另一个决策面（拖拽落点对应哪条状态迁移、是否唤醒），不是 UI 对齐。
- **pin-strip**：原型消息流上方的置顶条，用户未点名；`CONTEXT.md` 里没有对应对象。
- **消息 hover 工具条与 reaction**：原型有（含「转为任务」`data-convert`，`alibot-app.html:1147`），但 reaction 在本仓没有数据面与语义；用户未点名。**注意**：「转为任务」与面 6 是同一件事的另一种入口，本轮只做 composer 工具行那一个入口，不顺手加 hover 工具条。
- **原型能力开关里的 `dedupe` / `backfill`**（`alibot-app.html:1296-1297`）：本仓没有任何可去重的数据面，也没有所有权门禁；照抄只会造两个永远不生效的开关。本轮只落 `auto-claim`（用户点名）。
- **Agent「日志」页签**：用户人定不做本体（D24），但**另立一张 backlog 票记入口**（见 Further Notes）；该票不属本轮实施序列。
- **原型的假观测值**：`Token 消耗` / `上下文占用 72%` / `内存占用` / `运行时长` / `平均延迟` / `温度` / `工具权限`（`alibot-app.html:967-973` 的 `RUNTIME` 与写进 DOM 的 Susan 统计）。用户人定「运行时页签只放 `agent_config` 里真实存在的字段」，因此这些**一律不渲染成真值**，也不进本轮的任何票。
- **把「暂停」实现成「从唤醒面排除」**：暂停只写 `agent_config.enabled`（ADR-0011）；真静默（不唤醒、不记轮次结果）是唤醒面的另一个决策，本轮不做。

**本轮不做的相关能力**

- **附件**不做：搜索命中附件、把附件内容喂给 Agent（成员面）、删除附件、富媒体预览（只做上传 / 绑定 / 渲染 / 下载）。理由见 ADR-0014。
- **历史消息不随语言重渲染**：追加不改写、不回填（ADR-0001），切换语言后历史 `system` 消息保持写入时的语言。
- **后端 CLI 文案不加双语**：`app/alibot/__main__.py` 与 `app/alibot/repair.py` 的中文是**命令行**诊断文案，人不在浏览器里读它们；本轮的双语范围是「浏览器可见」，不扩张到 CLI。
- **本票不改 `alibot-design-system/**`**：q1 把该目录的写面**授权给了主题实施票**（深色 token 族 + 必要预览页 + 包内自己的 ADR），**不是给本票**——本票仍然只写 `app/specs/**`、`CONTEXT.md`、`docs/adr/**`。两处需要显式登记的包内冲突：
  - `SKILL.md:145` / `DESIGN.md:269` 的「UI locale is Simplified Chinese」在本轮之后不再完整（处置见 Implementation Decisions §4）；**该句的修订不在授权内**（扩面是为深色 token 族），因此它是**登记在案的冲突**而不是被静默忽略的事项；
  - `DESIGN.md:304` 的「no dark theme」正是主题实施票要消除的缺口，本轮以它作为「主题必须单独立票」的依据。
- **不做主题的暗色推导以外的其它视觉扩展**：不新增色相、不改既有 token 名、不动三个产品角色族的既有取值（深色取值属主题票）。不新增任意数值档位、不做成员级或工作区级的其它设置项、不把设置面扩张成通用 key-value 存储（**工作区设置** 词条 `_Avoid_` 明写）。

**已知代价（明确取舍，不是遗漏）**

- **认领会重置一次预算**：按 q4 的裁定，首次认领开该 task target 的世代并把用量重置满额。这与「预算约束的是一次人类发言能引发多少 Agent 往返」有一处张力——认领的触发者是人（人创建了任务），但推进世代的动作由**编排**执行。风险由「**每张任务至多一次**」这条构造性保证封住：没有它，Agent 就能靠反复认领给自己刷预算（详见 ADR-0010）。
- **暂停不等于静默**：暂停后该 Agent 仍会被唤醒、仍会落一条 `failed` 轮次结果（可读原因为「模型配置已停用」），只是不产出回复、状态点为未启用（ADR-0011）。
- **历史语言混合**：切换语言后，之前落库的 `system` 消息仍是原语言（ADR-0009）。
