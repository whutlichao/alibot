Part of #1（首版规格锚点）。

> **本票是规格正本，不是实施票。** 正文依据用户于 2026-10-16 的人定裁定定稿，并拆成三张实施票；本票不改生产代码或测试、不执行实施，也不改写 #1 / #23。
>
> **范围提示**：只处理回应预算的可配置、频道设置写入口、只读呈现与默认值实测依据；不扩展其它频道/成员/工作区设置能力。

## Problem Statement

当前回应预算的内置上界是 `BUDGET_LIMIT = 3`（`app/alibot/db.py`），频道人类面只有只读的
`GET /api/channels/{id}/budget`（`app/alibot/api.py`）；工作台没有预算设置 UI，也没有上界写入端点。于是用户看不到
当前已用 / 剩余，也不能在页面上调整频道上界。

跳数与预算作用域已经由 ADR-0004 泛化：每个 target 独立，`target_budget(target_id, epoch_seq, used)` 中的
`used` 是跳数唯一正本，不是轮次结果行数之和。后端在消息落库开启人类世代时重置 `used`，并只在一次实际投递
Agent→Agent 跳时推进；预算耗尽仍是零投递，消息照常落库。人类面写上界不能因此变成写用量。

现有默认值 3 源于 #1 的有界响应策略裁定，并由 ADR-0002 记录；仓库没有支持“3 这个具体数值”的成本模型、对比
实验或 token / 时延 / 金额读数。因此要将“配置能力”和“3 是否合适”分开：先保持默认 3 并允许频道选择固定档位，
再由独立实测票复核依据；不能把一个新猜测替换旧猜测。

## Solution

将回应预算上界作为可由频道设置修改、可持久化、可读回的配置，同时继续由后端独占管理用量。以下决定均来自
**用户 2026-10-16 定夺，裁定方式：人定**：

1. **人类面写入口选 W1**：频道设置新增 `PATCH /api/channels/{id}/budget`。人类面只能写上界，不能写或重置 `used`。
2. **配置落点选 L2**：库内逐频道配置；未配置的频道回落到内置默认常量。排除进程环境变量 L1、工作区级 / 成员级 L3。
3. **固定档位**：可选 3 / 5 / 10，内置默认仍为 3。是否应改变默认 3 的具体数值不在本规格裁定，由 ADR 实测票复核。
4. **生效时机**：更改后的频道上界从下一个人类世代生效；当前世代继续按既有生效上界计算，不回溯修改 `used`。
5. **ADR-0002 处置**：保留原文，不修订、不取代。默认仍为 3 且耗尽仍零投递；另新增 ADR-0007 记录“人类面只能写上界、不能写用量”的边界收窄。
6. **实施拆分为三票**：① 配置落点 + 只读呈现；② 人类面写入口 + ADR，blocked by ①；③ ADR 实测依据 + 默认档位复核，blocked by ②。

页面需要把当前世代的已用 / 剩余、当前有效上界及其来源展示清楚；若频道已保存一个下一世代才生效的新上界，
需与当前世代的有效上界区分展示，避免把待生效配置误读成当前额度。

## User Stories

**A. 看见回应预算**

1. 作为本机用户，我想在频道设置中看到当前人类世代的已用跳数与剩余跳数，这样我能判断预算状态而非等到 Agent 停止响应才猜测。
2. 作为本机用户，我想看到当前世代实际生效的上界及其来源（频道配置或内置默认），这样我知道读数来自哪一层。
3. 作为本机用户，我想看到保存的频道上界与当前世代上界在不同世代间有差别时被明确区分，并标注新值从下一世代生效，这样我不会误以为当前剩余量已改变。
4. 作为本机用户，我想在预算耗尽时看到明确的“预算耗尽”事实，而不是误读成 Agent 出错。
5. 作为本机用户，我想在重启后仍看到相同的当前世代 `used` 与有效上界，这样显示值与后端压制行为仍是同一条事实。

**B. 调整频道上界**

6. 作为本机用户，我想在频道设置页修改该频道的回应预算上界，而不用改源码或进程环境。
7. 作为本机用户，我想从 3、5、10 三个固定档位中选择上界，默认仍为 3，这样选择范围有明确定义且不改变现有默认行为。
8. 作为本机用户，我想让配置只影响被设置的频道，并在未配置时回落到内置默认，这样不会无意改变其它频道。
9. 作为本机用户，我想在保存后读回新配置，并知道它从下一人类世代生效，这样保存结果可确认且当前世代不会被回溯改写。
10. 作为本机用户，我想让页面及 API 拒绝对 `used` 的写入，即使提交了该字段也不能清零或伪造已用跳数，这样用量正本仍由后端维护。
11. 作为本机用户，我想让非法档位被明确拒绝且配置不留下半成品，这样回应预算始终是合法的固定档位。

**C. 保持有界响应语义**

12. 作为本机用户，我想让后端在人类消息成功落库并开启新世代时将 `used` 重置为 0，且新世代使用当时生效的频道上界，这样重置时点与消息落库事实一致。
13. 作为本机用户，我想让每次实际投递 Agent→Agent 跳只推进一次 `used`，无论唤醒了几个成员，这样跳数口径不会受成员数影响。
14. 作为本机用户，我想让每个 target 的预算互相独立，这样一个 target 耗尽不会锁住其它 target。
15. 作为本机用户，我想让目标全部处于 in-flight、没有实际投递的合并唤醒不消耗预算，这样“跳”仍表示一次投递事实。
16. 作为本机用户，我想让并发 Agent 消息不能越过当前世代的有效上界，这样可配置不削弱硬上界。
17. 作为本机用户，我想在当前世代预算耗尽后让 Agent 消息照常落库、但不投递任何唤醒，并为每个被压制成员留下 `budget-exhausted` 轮次结果，这样“没回应”有可追溯解释。
18. 作为本机用户，我想让后续人类世代重新按新的有效上界开始，而不修改既有消息或轮次结果，这样预算配置不会改写历史。

**D. 说明默认值依据**

19. 作为本机用户，我想知道默认 3 是既有策略裁定而不是已实测得出的数值，这样我不会把策略当成成本结论。
20. 作为本机用户，我想看到至少一种本机模型与一种远端付费模型的 token、时延和成本读数，这样可以评估默认档位在不同 provider 上的代价。
21. 作为开发者，我想在隔离数据目录中复现“跑满一个人类世代”的测量过程，并记录输入模型、价格与环境，这样 ADR 依据可复核。
22. 作为开发者，我想让任何默认值变化都需要基于实测新增 ADR，而不是静默改动内置常量，这样 ADR-0002 的结论不会无记录漂移。

**E. 文档与验收**

23. 作为开发者，我想让 `CONTEXT.md` 中人类世代、回应预算、跳、预算耗尽、预算表五条词条使用配置后的通用术语，而不再把上界写死为 3。
24. 作为开发者，我想让测试断言外部可观察的预算状态、写入边界与压制结果，而不是依赖私有常量或把默认 3 写死在通用行为断言中。
25. 作为项目维护者，我想将工作拆成三张可独立验收的纵向票，并以原生依赖明确先后关系，这样每张票都有清晰的可交付行为。

## Implementation Decisions

### 1. 已核实的事实基线

| 事实 | 来源 |
| --- | --- |
| 内置上界为 `BUDGET_LIMIT = 3`；现有频道预算 API 是只读，没有页面配置入口 | `app/alibot/db.py`、`app/alibot/api.py`、`app/alibot/studio/` |
| 预算是一份 per-target 事实；`target_budget` 保存 `epoch_seq` 与 `used`，其中 `used` 是跳数唯一正本 | ADR-0004、`app/alibot/db.py`、`CONTEXT.md`“预算表” |
| 人类消息落库开启新世代并重置用量；实际投递的 agent→agent 跳推进一次用量；零投递不扣跳 | `app/alibot/db.py` `append_message` / `consume_budget`、`app/alibot/orchestration.py` `_spend_jump` |
| 耗尽时 Agent 消息仍落库但不产生唤醒；每个被压制成员有对应轮次结果 | `app/alibot/orchestration.py` `_record_budget_exhausted` |
| 3 来自既有策略裁定；没有 token / 时延 / 金额测量支持该具体数值 | #1 已确认边界、ADR-0002；本仓无对应实验结果 |

### 2. 已裁定的配置契约

- **人类写入口**：频道设置界面通过 `PATCH /api/channels/{id}/budget` 修改上界。请求只能表达上界；人类面不得写 `used` 或触发用量重置。
- **配置层**：上界是库内逐频道配置。无频道覆盖时回落到内置默认常量；不使用进程环境变量、工作区级或成员级配置。
- **可选值**：固定档位 `{3, 5, 10}`，内置默认 `3`。不支持任意整数、0 或 1；非法值必须明确拒绝，不部分写入。
- **生效时机**：频道上界变更从下一个人类世代起生效。当前世代保留原有效上界及 `used`；页面读数须能区分当前有效上界与下一世代将用的已保存配置。
- **用量边界**：`used` 仍由后端独占维护：开世代动作落库时重置，且仅在一次实际投递跳时增加一次。其正本仍是 `target_budget.used`，不能从 `round_outcome.consumed_budget` 求和。
- **配置与使用量分离**：持久化配置与每 target / 每世代的用量事实必须各自可读；具体数据库列或表形态属于实施细节，但后端裁决与只读面必须取同一当前有效上界。
- **直接推论核实**：W1 的 `/api/channels/{id}/budget` 将设置范围限定在一个频道；ADR-0004 规定 channel 型 target 复用 `channel.id`。因此 L2 库内逐频道配置与写入作用域一致；L1 进程设置和 L3 工作区 / 成员设置不符合该边界。本规格未发现需要改判或升级的矛盾。

### 3. ADR 与五条词条的处置

- **ADR-0002：保留原文，不修订、不取代。** 默认仍为 3，耗尽零投递取舍不变；ADR-0004 已将作用域从频道泛化到 target，不由本票重写。若实测票要改变默认值，必须另以新 ADR 明确取代相关结论并记录实测与代价。
- **新增 ADR-0007**：记录人类面只可修改上界、不能修改用量的边界变化；不把它误写成 ADR-0002 已被推翻。
- **`CONTEXT.md` 五条词条均已处置**：人类世代、回应预算、预算耗尽、预算表泛化为当前有效上界与后端用量正本；跳的定义保持不变，因为跳数口径没有改变。上界不再被固定定义为 3。

### 4. 三张实施票及依赖

1. **配置落点 + 只读呈现**：建立库内逐频道配置与内置默认回落的读取路径；页面展示当前世代已用 / 剩余、当前有效上界及其来源，并能与下一世代待生效的频道配置区分。可独立验收默认值回落、持久化读数及来源呈现。**无 blocker。**
2. **人类面写入口 + ADR**：频道设置页面通过 `PATCH /api/channels/{id}/budget` 保存 3 / 5 / 10 上界；当前世代不变、新值下个世代生效；拒绝用量写入；完成写入与读回行为及边界 ADR。**blocked by ①。**
3. **ADR 实测依据 + 默认档位复核**：隔离环境下量 token、时延、provider 成本，比较至少一种本机与一种远端付费模型；形成可复核证据与 ADR，复核默认 3 是否合理及其在固定 3 / 5 / 10 档位中的位置。任何默认值变动都必须由新 ADR 记录。**blocked by ②。**

实施票均为纵向 tracer bullet，必须包含自身可演示 / 可验证的行为与验收条件；依赖边由 GitHub 原生 `blocked_by` 关系表达，不以正文文字替代。

## Testing Decisions

**好测试只断言外部可观察行为**：HTTP 读数、设置后读回、世代切换时生效、后端重启后持久性、`used` 的后端写入边界、实际投递 / 零投递和轮次结果；不把内部常量作为通用契约。

- **配置与只读呈现票**：覆盖未配置回落为 3、频道配置来源、已用 / 剩余与当前上界、下一世代待生效值，以及重启后的持久事实。
- **写入口票**：覆盖频道间隔离、3 / 5 / 10 合法值、非法值拒绝且无部分写入、`used` 不可由人类写入、修改下一世代生效，以及原有预算耗尽与并发上界行为不变。
- **实测票**：脚本化替身只用于行为测试；成本实验必须用真实模型，测试数据目录隔离。采集 `Msg.usage` token、`round_outcome.started_at / finished_at` 时延，并用记录的模型价格换算成本；样本至少包含本机 provider 与远端付费 provider，记录模型版本、环境、价格来源与测量条件。付费模型运行由实施方在其授权环境人工触发，本票不使用凭证或产生费用。
- **接缝与先例**：沿用现有 HTTP 黑盒与 `create_app` 的手动调度器 / 脚本化 Agent seam，预算行为测试参考 `app/tests/test_bounded_relay.py` 与 `app/tests/test_target_scope.py`；不新增测试接缝。本票不运行源码测试。

## Out of Scope

- 本票不改 `app/alibot/*.py`、`app/alibot/studio/*`、`app/tests/*`，不实施任何配置 API、UI、数据库变更或实测。
- 不配置进程环境变量、工作区级或成员级上界；不提供任意数值档位，不允许人类面写 `used`。
- 不改变预算耗尽的零投递语义、跳数定义、target 作用域、并发上界或消息落库纪律。
- 本票不改变默认值 3；是否需要将默认改为 5 或 10 留给实测票用证据复核，任何改值须有新 ADR。
- 不修改 ADR-0002、ADR-0004、#1 或 #23；不运行真实模型、不读取凭证、不触发付费请求或操作用户真实数据。
- 不新增成本仪表盘、预算跨频道聚合、成员级权限或其它产品设置能力。

## Further Notes

- **裁定来源与方式**：W1 写入口、L2 库内逐频道落点、固定 3 / 5 / 10 档位且默认 3、下一人类世代生效、三票拆分及依赖，均为**用户 2026-10-16 定夺，裁定方式：人定**。不存在等待用户或实施者决定的本票级别未决项。
- **ADR-0002 结论**：本次选“保留”，不是修订或取代；新建 ADR-0007 仅记录 W1 打开的写入边界。实测票若改变默认，另行建新 ADR 并说明与 ADR-0002 的关系。
- **术语纪律**：沿用 `CONTEXT.md` `## Language` 的人类世代 / 回应预算 / 跳 / 预算耗尽 / 预算表；`target_budget.used` 是跳数正本。
- **拆票顺序**：① 配置落点与只读呈现 → ② 人类面写入口与边界 ADR → ③ 实测依据与默认档位复核。② blocked by ①；③ blocked by ②。三个 issue 均作为 #31 的 sub-issue，并打 `ready-for-agent`。
- **不越权同步**：#23 当前预算机制的规格不在本票授权修改范围；本票只记录未来实施需遵守的配置决定，不对 #23 做任何写操作。
- **规格正本**：GitHub issue #31 body 与本文件正文逐字一致；Answer 评论只记录执行回执、证据、票据编号、依赖、提交与 PR 信息。
