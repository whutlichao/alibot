## Problem Statement

学生在 Studio 的 Agent 详情页上看到的是**一页越堆越长的列**，而不是三类分得开的配置面。今天这一页把五件事
纵向排在同一列（统计 → 系统提示 → 配置（含 MCP 表单与技能列表）→ 全局 MCP 只读小节 → 危险操作），用户具体
遇到五件事：

1. **改一个字段要滚过一整页。** 配置区里混着三项用户从未因为「想调这个数字」而打开的字段（上下文条数 /
   压缩阈值 / 迭代上限），真正常改的字段被挤到需要滚动。
2. **技能区挤成一团，而且看不到正文。** 技能段同时挂着列表、手填绝对路径安装、上传 zip 安装、勾选式导入、
   每行「复制到其他成员」弹层；而用户想「看这个技能到底是什么」时，页面上**没有正文入口**——只有名字、
   描述与前 12 位 hash。
3. **`mcp.json` 只能看不能改。** 详情页的「全局 MCP」是只读行，后端只有一条只读视图端点；想改一条声明，
   人得离开浏览器去编辑家目录里的 JSON，改错了没有任何前置校验。
4. **两块 MCP 面互不说话。** 库行（装配正本）与家目录文件（导入源）在同一页上是不相邻的两段，谁也不标注
   「我是哪一份数据」，用户看不出同名时谁胜出。
5. **危险操作与配置混在一起。** 暂停 / 恢复与删除和配置字段同列滚动。

这五件事是同一个缺口：这一页**没有分组**。用户的心智是三类——「这个 Agent 是谁、怎么配的」「它会哪些技能」
「它连哪些 MCP」——而界面把它们摊成了一列。

## Solution

把 Agent 详情页分成**三个页签**：

- **「基础信息和配置」**：统计 → 系统提示 → 配置 → 危险操作。三项上下文数字（上下文条数 / 压缩阈值 /
  迭代上限）的**界面入口整体撤掉**；库内既有值与后端默认行为一字不动。
- **「skills」**：**双栏**。左栏是当前 Agent 的技能列表 + 一个**下拉框**式的「从本机导入」；右栏是选中技能的
  详情——元数据（名称 / 描述 / 来源路径 / 内容 hash / 启停态）**加上 SKILL.md 正文**，下面挂启用 / 停用与删除。
  安装方式只留「从本机导入」一条。
- **「mcp」**：**两块**。上块是表单（增删改**库行** `mcp_server`，`scope_kind='agent'`，装配正本）；
  下块是**直接编辑家目录 `mcp.json`** 的文本域（保存前校验 JSON 与声明形状）。两块各标注数据来源与
  「同名时库行胜出」。原「全局 MCP」小节并入这一页签。

  > **2026-10-28 用户反馈覆盖**：两块的数据来源标注、「MCP 声明」标题与「全局 MCP（只读）」标题已撤除；
  > 功能面（库行增删改 / 启停 / 确认、原文文本域 / 保存、条目读数）不变。读端点响应另增 `path`
  > （该成员 `mcp.json` 的真实路径，供缺失提示使用）。以 D7 的注记为准，见 PR #335。

两处新读写面（技能正文只读、`mcp.json` 读写）都落在既有资源族里，**零新增服务模块**；`mcp.json` 获得
Studio 写面与 ADR-0031 §四 / §六 的既有口径相向，**同票收口**（改既有 ADR，判为修订而非新决策），并在
#275 留方向调整评论。#275 的剩余范围（导入命令 `migrate-mcp` + 移除装配层）不变。

## User Stories

**A. 页签分组与导航**

1. 作为本机用户，我想让 Agent 详情页分成「基础信息和配置」「skills」「mcp」三个页签，这样我能按「这是谁／它会什么／它连什么」三类直接跳到位。
2. 作为本机用户，我想让三个页签的顺序固定为「基础信息和配置 → skills → mcp」，这样位置记忆不会每次变。
3. 作为本机用户，我想让打开详情时默认停在「基础信息和配置」页签，这样我不会每次都被带到别的页签。
4. 作为本机用户，我想让切到另一个成员时页签回到默认那一页，这样新成员不继承上一个成员的页签位置。
5. 作为本机用户，我想让页签用键盘也能抵达与切换（`role="tablist"` / `role="tab"` / `aria-selected`），这样我不用鼠标也能换页。
6. 作为本机用户，我想让页签只切呈现、不丢我正在编辑的草稿，这样我切去 skills 看一眼再回来，输了一半的系统提示还在。
7. 作为本机用户，我想让「有未保存的改动」的保存条跨页签可见，这样我在 skills 页签里也知道配置还有没保存的改动。
8. 作为本机用户，我想让当前的页签有可读的选中态（`aria-selected="true"` + 选中样式），这样我不会分不清自己在哪一页。
9. 作为审查者，我想让页签容器用新的类名而不是既有 dock 的 `.dock-tabs`，这样「详情是主线视图、不是 dock 形态」这条既有结论不被字面混淆。

**B. 基础信息和配置页签**

10. 作为本机用户，我想让统计、系统提示、配置、危险操作按这个顺序排在第一页签里，这样我最常改的系统提示仍紧贴统计之下。
11. 作为本机用户，我想让危险操作仍是这一页签的**最后一块**，这样误触面离配置字段最远。
12. 作为本机用户，我想让上下文条数、压缩阈值、迭代上限三格从界面上消失，这样配置区只剩我会改的字段。
13. 作为本机用户，我想让撤掉那三格之后保存**不会把它们清空**，这样库里原来的 40 / 0.7 / 30 不会被一次保存抹掉。
14. 作为本机用户，我想让后端 `PATCH /api/agents/{id}` 的字段面与库里的三列都原样保留，这样我自己写脚本调用时行为不变。
15. 作为本机用户，我想让那三格的界面文案键随控件一起消失，这样词条表里不留没有消费点的孤儿键。
16. 作为审查者，我想让「界面撤掉」与「后端字段保留」的边界写死在文档与验收项里，这样下一位读者不会顺手把列或 PATCH 字段一起删了。

**C. skills 页签 · 布局与详情**

17. 作为本机用户，我想让 skills 页签是双栏：左栏列表、右栏详情，这样我点一个技能就能在右边看它是什么，列表不会被详情挤走。
18. 作为本机用户，我想让左栏每行显示名字、启停徽标与描述摘要，这样我能在同一屏里比较几个技能。
19. 作为本机用户，我想让左栏当前选中的那一行有可读的选中态，这样我知道右栏在讲哪一个。
20. 作为本机用户，我想让右栏显示名称、描述、来源路径、内容 hash 与启停态，这样我在界面上就能核对「装的是哪一份」。
21. 作为本机用户，我想让右栏显示 SKILL.md 的**正文**，这样我不用去翻家目录就知道这个技能的指令到底写了什么。
22. 作为本机用户，我想让正文按原样保留换行与缩进呈现，这样 front matter 之后的指令块仍然可读。
23. 作为本机用户，我想让正文来自一个只读端点而不是塞进列表响应，这样列表仍然轻、正文按需读。

26. 作为本机用户，我想在正文文件读不出来（权限 / 非 UTF-8）时看到与「缺失」不同的空态说明，这样我知道该去修什么。
27. 作为本机用户，我想在左栏为空时右栏给一句空态指引，这样新装的 Agent 不会看到一片空白。
28. 作为本机用户，我想让切到 skills 页签时默认选中左栏第一行，这样我不必先点一下才看得到内容。
29. 作为本机用户，我想让列表重读后若选中项已不存在就回落到第一行，这样删掉一个技能后右栏不会停在一个已删的技能上。
30. 作为审查者，我想让正文按**纯文本**呈现（不解析 Markdown），这样本仓不新增一个转义 / XSS 面。

**D. skills 页签 · 从本机导入（下拉框）**

31. 作为本机用户，我想让 skills 页签的安装方式只剩「从本机导入」一条，这样我不必再在三个入口之间判断该用哪个。

## Implementation Decisions

### D1 · 页签结构与归属

三个页签，顺序固定：**基础信息和配置** → **skills** → **mcp**。

| 页签 | 装什么 | 内部顺序 |
| --- | --- | --- |
| 基础信息和配置 | 统计 / 系统提示 / 配置（剩余字段）/ 危险操作 | 统计 → 系统提示 → 配置 → 危险操作 |
| skills | 顶部「从本机导入」下拉框；双栏：左栏技能列表、右栏选中技能详情 | 导入 → 左栏 / 右栏 |
| mcp | 上块库行表单；下块 `mcp.json` 文本域 | 库行块 → 文件块 |

**标识与词条**：`data-adtab="base|skills|mcp"`；节点 `#adTabBase` / `#adTabSkills` / `#adTabMcp`；
容器类名 `.ad-tabs`（**不复用** `.dock-tabs`）；词条键 `agentDetail.tabsLabel` / `tabBase` / `tabSkills` /
`tabMcp`。旧页签名 `tabOverview` / `tabRuntime` **不复用**、不复活。

**状态**：`state.agentDetailTab ∈ {'base','skills','mcp'}`，默认 `'base'`；打开详情与切换成员时重置；
**不落库、不写 URL、不记忆上次页签**。

面板 `role="tabpanel"`。键盘靠浏览器原生 `<button>` 的 Tab / Enter，**不自造方向键漫游**。

### D4 · 导入入口 = 下拉框，一次一个

**形态（用户已定）**：点击「从本机导入」**展开一个下拉框**——不是弹窗、不是多选勾选列表。

**语义**：**单次选择一个候选、导入一个技能**。候选端点逐条降级（每条带可导入 / 原因 / 已安装），单选让
409 与各类失败原因精确归到那一条；写路径逐字复用既有安装端点（`source_path` = 候选路径），一条请求一条技能。

**下拉框内容**：按状态分三组——可选、已安装（禁用）、不可导入（禁用 + 原因写在选项文本里）；
**默认不预选**。候选来源目录缺席时不渲染下拉框，只给空态指引（应用不创建那个目录，那是别人的落点）。

**刷新**：导入结束（成功 / 同名跳过 / 失败）后重扫候选 + 重读技能列表；下拉框回到空选择。

### D5 · skills 右栏详情 + SKILL.md 正文只读端点

**右栏内容（自上而下）**：元数据（名称 / 描述 / 来源路径 / 内容 hash / 启停态）→ 动作（启用 / 停用、删除）
→ **SKILL.md 正文**。正文按**纯文本**呈现（保留换行与缩进），**不**解析 Markdown。

**端点**：`GET /api/skills/{skill_id}/markdown`（落在 `/api/skills/{id}` 同族子资源）。

| 情形 | 响应 |
| --- | --- |
| 成功 | `200`：既有元数据载荷 + `markdown`（正文）+ `state="ok"` |
| 字节缺失（行在、目录或 SKILL.md 不在） | `200`：元数据照常 + `markdown=null` + `state="missing"` |
| 路径不安全（根外 symlink 祖先 / 根外目标） | `200`：`markdown=null` + `state="invalid"`（不回任何根外内容） |
| 读不出来（权限 / 非 UTF-8） | `200`：`markdown=null` + `state="unreadable"` |
| `skill_id` 不存在 | `404`：复用既有「技能不存在」文案 |
| 行是弃用的频道级旧行 | `400`：复用既有「只接受成员作用域」文案（旧行没有家目录字节） |

**守卫**：正文读取经全局只读守卫同族的 `realpath` 判定（以全局根为根，拒绝根外 symlink 祖先与根外目标），
参数与技能装配读同一份字节、同一道守卫。守卫拒绝 ⇒ `state="invalid"`，**不**退化成直读。

**选中态**：进入页签默认选中左栏第一行；列表重读后选中项不存在则回落第一行；列表为空则右栏给空态。

### D6 · skills 动作范围；复制弹层撤除；`/copy` 端点保留

保留：右栏「启用 / 停用」（既有 PATCH 端点）与「删除」（既有 DELETE 端点），作用于当前选中的技能。

撤除：**「复制到其他成员」弹层与其入口**。该弹层是 MCP / 技能**两 kind 共用**的一份实现，因此连带后果是
技能行与 MCP 行的复制入口一起消失——那是同一份呈现状态的收缩，不是两件事。相关函数、呈现状态与
「复制后清缓存」的清理逻辑一并删除，不留死代码。

**端点处置（人定）**：`POST /api/skills/{skill_id}/copy` **后端保留**，其契约测试原样保留、原样绿；
`api.py` 模块 docstring 或该端点 docstring 加一行注明「当前 Studio 无入口，保留为脚本 / API 用法」。
不采纳「同票删端点」（不可逆收缩 + 与设计票 Ownership 冲突）与「标注弃用」（把「暂留」写成「已弃用」，
将来真删还要再改一次文档）。MCP 行的复制走既有 `POST /api/mcp-servers`，无专用端点，故无对应说明。

### D7 · mcp 页签 = 库行表单 + 直接编辑 `mcp.json`

> **2026-10-28 用户反馈覆盖（以本条为准）**：界面上的「MCP 声明」标题、库行来源说明、环境变量说明、
> 文件来源说明与「全局 MCP（只读）」标题已撤除；下文出现的「标注」按历史决策保留，不再要求渲染。
> 读端点响应增加 `path` 字段（真实路径；缺席时给目标路径，路径越界为 `null`），缺失提示用它。
> 功能面与端点校验不变，见 PR #335。

**上块（库行表单）**：列表 + 表单 + 启停 + 删除 + 远端数据面确认，沿用既有能力段的 MCP 部分与既有端点
（作用域恒为当前成员）。标注：**库行 `mcp_server`（`scope_kind='agent'`），装配正本**。

**下块（`mcp.json` 文本域）**：新增两条端点，落在既有全局 MCP 视图端点同族。

| 端点 | 契约 |
| --- | --- |
| 读 | 返回成员 id、文件是否存在、文件原文（不存在时为空串）、条目计数；成员不存在 ⇒ 404（与既有视图端点同一条成员校验） |
| 写 | 请求体是整份 JSON 原文；校验通过则**原样写盘**并回刷新后的读数；校验失败 ⇒ `400` + 可读原因 + 字段级错误，**零写入** |

**保存前校验三道，全部在写盘之前**：① JSON 可解析；② 顶层是对象且 `servers` 是数组；③ 每条经既有的声明
归一化内核校验（transport / command / args / url / `env_names` 形状）——与库写路径、全局文件读路径**同一份
实现**，因此校验口径与装配层逐字同源。

**写盘**：先写同目录临时文件再原子替换；**保留用户自己的键序与缩进**（不重排、不重新序列化回写、不格式化）。
文件不存在且成员家目录存在 ⇒ 新建；家目录本身不存在 ⇒ `400`（应用不自动创建全局层）。文件存在 ⇒ 覆盖
（人类显式动作）。

**守卫**：读经全局只读守卫；写前用同一内核取目标 `realpath` 并拒绝根外 symlink 祖先与根外目标。

**优先级标注（界面文案，不改变装配）**：上块「来自库行、装配正本」；下块「来自成员家目录文件；**同名时
库行胜出**，落选条目会进轮次结果的可读提示」。远端条目的数据面确认仍走既有动作，文本域不绕过它。

**与 #275 的关系**：本能力只给文件加**写面**，不改装配层、不删「过渡期只读装配层」这条降级路径；
#275 的剩余范围（导入命令把既有条目一次性搬进库行、移除装配层）不变。

## Testing Decisions

### T1 · 什么算好测试

只断言**外部可观察行为**：`data-od-id` / `data-adtab` 的存在与顺序、`aria-*` 状态、节点文本取词条值、发出的
HTTP 请求（URL + body）、后端状态码与响应形状、写盘后的文件字节。**不**断言私有函数名、内部状态字段名、SQL、
目录遍历顺序。断言 Markdown 正文时断言「与磁盘上 SKILL.md 的正文逐字相等」，不写死一段示例文案。

### T2 · 呈现层用例（既有缝，不新开框架）

- **落点**：`app/tests/agent_detail_ui.test.cjs`（页签骨架 / 内容归属 / 上下文三项撤除 / 保存载荷）、
  `app/tests/agent_capabilities_ui.test.cjs`（skills 双栏与下拉框 / mcp 两块 / 复制弹层撤除）。
- **装置**：沿用既有 `vm` + DOM 替身 + fetch 替身；不新开第二套前端测试框架。
- **先例**：区块顺序断言、PATCH 载荷逐字段断言、候选分组与禁用断言。

### T3 · HTTP 契约用例（既有缝）

- **落点**：技能正文端点与 `mcp.json` 文件端点各一组契约用例（可并入既有技能 / 全局 MCP 用例族；
  判据是不新开第二套装置）。
- **必测边界**：技能行不存在 ⇒ 404；弃用的频道级旧行 ⇒ 400；SKILL.md 缺失 ⇒ `missing`；根外 symlink ⇒
  `invalid` 且响应里不含根外内容；读不出来 ⇒ `unreadable`；写非法 JSON ⇒ 400 且文件 mtime 不变；写形状
  非法的单条 ⇒ 400；写合法 ⇒ 文件内容与提交文本**逐字相等**（不重排）；家目录缺失 ⇒ 400 且不创建目录；
  成员不存在 ⇒ 404。
- **装置**：真实临时 `HOME` 下的全局层树 + HTTP 黑盒。**不**读写真实的 `~/.alibot`。
- **先例**：既有技能复制端点的守卫拒绝与 404 文案、既有全局 MCP 用例族（真实临时 `HOME` + 家目录文件）、
  既有技能装配用例（装配读同一份字节）。

### T4 · 断言改写的真实性

每条旧断言要么**换成**对新形状的等价断言（顺序变了两段、载荷少三项要显式断言「不存在」），要么**删掉并
说明它断言的节点已不存在**（zip 安装入口、复制弹层）。判据：diff 里每条删除 / 改写都能指回 D1–D9 的一条决策。

### T5 · 不测什么

不测 Markdown 渲染（首版纯文本）；不测 `mcp.json` 的装配后果（既有装配用例已覆盖，写面不改装配）；
不测真实浏览器像素（本仓无浏览器测试框架）；不测 `POST /api/skills/{id}/copy`（端点未改）。

### N3 · 本设计里最容易做错的三格

1. **保存载荷**：前端不再提交三项 ⇒ 既有值保持；照抄旧载荷（提交 `null`）会一次清空 40 / 0.7 / 30。
